# MaaFramework 独立组件

本页描述 `feat/atomic` 当前源码。设备连接、任务执行、预览、Debug 与离线识别统一使用独立 MaaFramework SDK；本分支不加载、下载或分发 MaaCore。应用包携带服务和 C++ worker，不内嵌完整 SDK；开发启动也不自动运行 SDK 下载工具。首次使用前先在应用内安装 Framework，再准备并启用游戏资源。

## 安装与检查

在「设置 → 更新」的 MaaFramework 卡片检查兼容版本、下载安装，再应用已准备的组件。安装目录与自动更新开关独立保存；启用自动更新时后台检查并准备兼容组件，达到空闲边界后生效。关闭此项不改变应用或游戏资源的更新偏好。缺少或损坏 SDK 时明确提示安装，不回退旧核心、开发缓存或旧包内 SDK。

默认目录由数据根和应用平台决定：

| 环境                 | 默认根目录                                                               |
| -------------------- | ------------------------------------------------------------------------ |
| 源码开发             | `<data-root>/components/framework/`；默认数据根为 `<checkout>/config/`。 |
| macOS 安装版         | `~/Library/Application Support/Maa Verge/MaaFramework/`。                |
| Windows/Linux 安装版 | `<程序目录>/MaaFramework/`；AppImage 以 AppImage 文件位置为准。          |

根目录下以 `maafw-data-<数据根摘要>/generations/` 隔离不可变版本。用户可选择其他可写绝对路径，拒绝文件系统链接；修改目录只影响后续准备，不搬动当前、待生效或回滚版本。SDK 归档缓存位于业务数据根的 `cache/framework-downloads/`，与游戏资源下载分开。更多目录及卸载约定见[独立组件与资源](maacore-runtime.md)。

## 官方源与 Mirror酱

兼容版本、平台文件名、大小和 SHA-256 由 [runtime-assets.json](../3rdparty/maaframework/runtime-assets.json) 固定。目前仅允许 `v5.14.3`，这是当前 C API、worker 和资源适配器绑定的版本；独立更新不代表可加载任意最新 SDK。维护者升级清单须同时验证 ABI、原生版本、识别资源和各宿主行为。

官方来源为 `MaaXYZ/MaaFramework` 对应版本的 GitHub Release。Mirror酱复用更新页的启用状态、掩码 CDK 和下载代理，使用已确认的官方 `MaaFramework` RID 及 `stable` 完整包通道。只有版本、大小、SHA-256 均等于固定资产时使用镜像；没有 CDK、平台缺包、元数据或下载失败、不兼容版本及摘要不符时使用官方源。检查和准备均读取当前偏好，填写 CDK 本身不会发起下载。

限时链接仅用于当次传输，CDK、完整链接和服务端原始错误不会写入更新记录或日志。下载卡片按实际传输显示 Mirror酱或官方源，回退后更新来源。来源选择不改变兼容版本及完整性要求，详见[Mirror酱更新分发](mirrorchyan.md)。

## 校验、切换与恢复

SDK 先解压到独立候选目录，拒绝路径越界及增量包；合法包内别名物化为独立普通文件，安装目录禁止符号链接和硬链接。保留依赖、上游许可与固定补充许可，生成逐文件完整性清单。离线原生探针实际加载 SDK 和最小资源，不建立设备 Controller、不调用 ADB。文件清单、固定版本和探针全部通过后才可激活。

Framework 的活动、候选和上一版本记录独立于游戏资源。设备执行、控制会话、画面读取、识别或异步原生操作未结束时等待空闲；切换时关闭闲置读者和原有 Controller，清除资源视图及帧缓存，使用新 SDK 重建原有连接。活动文件不原地覆盖，应用更新安装也须等待组件操作结束。SDK 激活不代表某个设备已成功重连，重连失败单独显示并保留诊断。

校验或切换失败保留原版本，可重新准备；上一份已验证代际可显式回滚。重新使用安装记录前复核清单，缺失或损坏时提示重新安装。游戏资源另由固定官方源码模型底包与 MaaResource 覆盖构成完整快照，启用前用 Framework 的无 Controller 探针核对；SDK 与资源的任何一条更新均不依赖旧核心版本。

`tools/prepare-maafw.mjs` 仍供维护者明确选择固定 SDK 做离线开发验证；产品不自动使用该缓存。应用包保留 C API 头文件来源、兼容资产清单及许可披露，Windows 可选离线资源也不携带 SDK。

## 验证边界

常规验证使用隔离数据根、合成 SDK 和 HTTP，不连接真实设备、不下载真实组件、不使用真实 CDK。原生协议夹具验证 Controller 共享、资源与 SDK 更新、忙时等待、清单及回滚；本机 macOS arm64 的打包和 Rust transport smoke 验证自包含服务及租约链路。上述结果不证明真实 SDK 下载、游戏行为、模拟器增强接口或其他宿主已验收；具体结果与限制见[开发状态](STATUS.md)。
