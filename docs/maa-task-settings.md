# 原版 MAA 常规任务设置对照

核对日期：2026-10-23。依据用户提供的常规设置截图、[官方手册](https://docs.maa.plus/zh-cn/)、[连接说明](https://docs.maa.plus/zh-cn/manual/connection.html)及固定版本 [v6.20.0 集成协议](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/v6.20.0/docs/zh-cn/protocol/integration.md)。在线手册可能先于当前核心更新，参数语义以固定版本实现为准。

| 原版任务 / 设置 | Maa Verge 入口与执行映射 |
| --- | --- |
| 开始唤醒 | 任务表「启动游戏」：客户端、启动开关、账号切换；`StartUp.client_type/start_game_enabled/account_name`。账号填写游戏内已登录账号显示名的唯一片段，留空不切换 |
| 多任务共用连接 | 启动游戏中的共享连接设置与「设备」页使用同一配置；ADB 路径、连接地址/配置、触控和增强截图在连接层应用，不作为 StartUp 参数透传 |
| 理智作战（可重复） | 每条「自动作战」独立设置关卡、药剂/源石、次数、材料目标和代理倍率；关闭用药/源石写入 0，关闭次数限制写入 `2147483647` |
| 代理倍率 | `series=0` AUTO、`-1` 保持游戏内设置、`1–10` 固定倍率。AUTO 及固定倍率仍取决于游戏版本、理智、剩余次数和核心资源支持 |
| 关卡指定 | 默认下拉显示常驻关卡与官方日历中的当期活动关卡，结合当前启用资源判断导航支持；勾选旁边“手动输入关卡”后输入任意关卡代码。龙门币 6/5 和经验 6/5 分别提交 `CE-6` / `LS-6`，核心负责第 5 关回退 |
| 指定材料 | `drops={物品ID:本次目标数量}`；表单提供常用材料和其他物品 ID。任一目标满足即停止；这是本次掉落目标，不是账户总库存保持 |
| 基建换班 | 常规、自定义、一键轮换；无人机用途、百分比心情阈值、11 项设施勾选/全选/清空；常规模式由核心排程，其他模式保留顺序设置。回收站、加工站、训练室、副手换人都有对应核心设施代码 |
| 自动招募 | 最大次数、3/4/5/6 星逐项确认、3/4 星招募时长、标签策略。确认 4/5 星时同步选择该星级标签；6 星与原版一样不提供新启用开关，已有高级配置可取消 |
| 信用收支 | 「信用商店」：好友访问、每日一次、借助战 OF-1、编队选择、自动购物与购买策略。信息板信用、线索交流、线索赠送在「基建换班」执行 |
| 领取奖励 | 七项独立开关：每日/每周任务、邮件、限定池免费单抽、幸运墙、限时开采、周年月卡、限时签到；分别对应 `award/mail/recruit/orundum/mining/specialaccess/signinevent` |
| 更新数据 | 应用任务 `UserDataUpdate`，独立勾选干员/仓库识别，选择每次/每日/每周；应用服务顺序调用 `OperBox` / `Depot`。界面显示所选/绑定设备最近成功同步时间 |

## 新建任务表与默认值

新建日常表按原版 v6.20.0 `InitializeItems` 的顺序添加：启动游戏、自动作战、基建换班、公开招募、信用商店、领取奖励、集成战略、生息演算、更新数据，全部继承原版 `BaseTask.IsEnable=true`。可以按需关闭长任务或调整顺序。已有任务表不被新默认覆盖。

名称自动选择尚未占用的“日常表1、日常表2”等；专项表使用“专项表1”等。必填的名称、任务列表和常规参数已填入可保存默认值。用户的会话草稿优先恢复；外部作业/视频文件、账号及本机模拟器路径仍须按实际情况指定，不生成虚构路径。

| 项目 | 新建默认值 |
| --- | --- |
| 启动 | 官服、自动启动；账号留空 |
| 作战 | 当前/上次关卡、不限次数、药/石均为 0、倍率 AUTO；企鹅物流和一图流汇报开启，可在表单关闭 |
| 基建 | 常规模式、全部 11 项设施、无人机下拉默认龙门币、心情阈值 30%；未进驻筛选、宿舍信赖、搓玉补货及三项信用/线索选项开启 |
| 公招 | 4 次、选择 4 星、自动确认 3/4 星、9 小时、自动刷新；不加急 |
| 商店 | 访问好友和自动购物开启、每日一次关闭；优先招聘许可，黑名单碳/家具/加急许可，不忽略黑名单、不限折扣 |
| 奖励 | 仅每日/每周任务奖励开启，其他六项关闭 |
| 集成战略 / 生息演算 | 傀影主题、刷分、999999 次并投资；沙洲遗闻有存档模式、荧光棒、16 批、清空商店 |
| 更新数据 | 干员与仓库均开启、每次执行 |

默认来源为固定版本的任务配置类及 GUI 序列化代码，而非用户截图中已修改的数值。新任务显式保存这些设置；旧任务缺失的高级参数仍保留既有适配行为。

## 活动日历与关卡

日历参考原版 v6.20.0 的 `StageManager`、`MaaUrls` 和 `MaaApiService`，优先从 [MAA 官方 StageActivityV2.json](https://api.maa.plus/MaaAssistantArknights/api/gui/StageActivityV2.json) 获取，主源失败后尝试同路径的 `api2.maa.plus`。主页和 `stages.list` 共用运行时内的日历与本地缓存，使用 ETag / Last-Modified 条件请求；默认每 6 小时校验，失败后退避重试，用户可手动刷新。缓存位于用户数据目录，不修改正在使用的不可变核心/资源 generation。

活动按客户端、真实起止时间和最低核心版本筛选；已过期的活动不会被资源版本中的旧名称重新认定为进行中。官方日历中的关卡还须具备已激活资源的导航支持；日历更新不能代替核心和资源更新。材料关卡按客户端 04:00 游戏日计算开放状态，资源收集全开活动也会生效。

联网失败时保留上次有效的官方缓存，并继续按当前时刻筛除已过期活动，同时显示缓存和更新状态。无有效官方日历时，读取已激活资源中的日历；精简资源可能仅有 `version.json` 活动标记，此时按活动名匹配相应导航关卡，标注“开放时间未确认”，不编造结束时间，也不将全部历史关卡当作当期活动。资源激活及每分钟刷新会重新计算关卡目录；任何已保存关卡值均保持，未知值自动进入手动模式。

## 应用层周期与成功证据

更新数据不是 MaaCore 原生任务类型，服务不能将 `UserDataUpdate` 直接提交给核心。两项识别分别记录成功时间，只有匹配当前任务的 `OperBoxInfo` / `DepotInfo` 提供 `done=true` 与有效结果，并确认任务完成、核心空闲后才更新。失败、停止、中断或仅有任务完成消息均不记为成功。普通干员/仓库识别任务与组合任务共享同一设备的时间记录。关闭两项会跳过该任务，已满足周期的项目也会跳过。

好友每日一次也是原版 GUI 逻辑。仅当匹配当前任务 ID 的 Mall `ProcessTask` 完成消息明确报告 `VisitLimited` 或 `VisitNextBlack` 时，才记录访问成功。购物任务结束不能代替访问证据。应用私有字段在提交前移除，不依赖核心识别未知开关。

每日与每周按客户端的游戏日计算：官服、Bilibili、繁中 UTC+8，国际服 UTC-7，日/韩服 UTC+9，04:00 换日，周一换周。执行时客户端依次取当前任务显式设置、表内之前的启动任务、设备最近成功启动的客户端、关联实例连接设置、全局连接设置和官服；`StartUp` / `CloseDown` 缺少 `client_type` 时按原版默认使用官服，与提交给核心的参数一致。作战掉落汇报缺少高级指定值时也继承该客户端，并对应 CN / US / JP / KR 服务器；用户显式值保留。

各设备 worker 先加载基础资源，再按客户端加载外服覆盖；覆盖缺失或加载失败会明确报错。任务客户端发生变化时只在目标设备空闲后重建 worker，保留原连接配置，确认连接与空闲后继续；停止或退出会取消准备，不重放结果未知的任务。此原生路径和参数隔离已用合成资源验证，仍需逐客户端真实游戏验收。

显式启动任务成功切换客户端或账号标识后，清除该设备之前的同步/好友访问周期记录，防止新账号被跳过。未配置账号标识的手工换号无法自动识别；此时应执行带账号标识的启动任务或选择每次同步。

## 尚需验收的部分

- 默认理智药、源石、加急许可授权继续为 0。截图中的 999 用药是原版用户配置，不作为 Maa Verge 的默认授权。任务参数仍同时受应用与本表额度约束。
- 公招加急尚未开放：固定版本忽略 `expedite_times`，无法把此字段作为可靠上限。表单明确禁用，高级参数请求继续拒绝；完整移植仍需实际消耗计数与停止机制。
- 官方日历联网失败时会标记缓存待更新；仅有资源活动名称的降级结果仍需核对游戏内开放期。材料目标列表不是完整物品数据库，其他物品 ID 可直接填写。
- 识别成功时间不等于完整库存/干员结果查看功能；专用结果面板、导出、库存保持仍按[兼容矩阵](maa-compatibility.md)推进。
- 合成 Worker、浏览器和类型检查不替代真实游戏行为验收。各客户端、模拟器、任务选项及平台需要分别记录核心版本、资源提交、参数与成功证据。
