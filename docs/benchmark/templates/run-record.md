# 单次运行记录模板

一份记录对应一次独立尝试，包括战前失败或基础设施无效尝试。空白/未知不能填为 0；模板不代表已有运行结果。口径见 [protocol.md](../protocol.md)。

## 关联与配置

| 字段                               | 值        |
| ---------------------------------- | --------- |
| attempt ID / 批次 / 协议修订       | 待填      |
| 场景 ID / 配置摘要                 | 待填      |
| 轨道 E/R、条件 C0/C1/C2、方法      | 待填      |
| 区组、重复编号、方法顺序、调度种子 | 待填      |
| 代码、模型、提示、资料和控制链摘要 | 待填      |
| E 初始计划或 R 的 P0 摘要          | 待填      |
| 关联的规划准备/资格验证记录        | 待填      |
| 设备脱敏标识与授权批次             | 待填      |
| 开始/终止 UTC、单调时钟域          | 待填      |
| 补跑关联的原 attempt ID 及依据     | 无 / 待填 |

## 开局与触发

- 阵容、技能、模组、模式、速度和预算核验：待填。
- 战前规划或方法预处理的启动时间、结果与消耗：待填；E/R attempt 从协议规定起点计量。
- 是否沿统一执行前缀到达触发点（仅 R）：待填。
- 未到达的原因与证据：无 / 待填，不直接删记录。
- 触发点游戏时间、击杀、费用、保护目标、场上干员、冷却及未知项：待填。
- 原始/感知观察索引和可见状态签名：待填。
- C1/C2 是否实际注入、作用动作、发生时间、实际幅度：待填。
- 策略得到的普通反馈与评测器私有注入记录：分别关联，不混入模型输入。
- R 的动作锁定、实际下发、统一验证、handoff 时间及交接时无旧命令待下发的依据：待填。E 无触发/交接字段记“不适用”。

## 每次计划修复

此节可按实际修复次数重复；B0 没有修改则填“无计划修复”，不能虚构图编辑。

- 触发观察、失效前提及证据：待填。
- 变化分类：信息补全 / 机制分支 / 时序资源 / 动作失败 / 感知错误，可多选并解释。
- 修复前后版本与不可回滚行动/资源历史：待填。
- 预测受影响集合、共享资源冲突、保留节点有效依据：待填。
- 实际节点/参数/依赖编辑和完整差异索引：待填。
- 因果边、条件边、资源调度边分别发生了什么变化：待填。
- 是否有必要的结构变化，还是参数调整/重试；复核证据和未知项：待填。
- 修复提交时间、校验通过时间、首个相关动作得到确认的时间：待填。
- 是否全局回退、理由与额外成本：待填。
- 误修复/遗漏的复核依据、复核者是否知道方法标签、争议：待填。

## 结局判定

- 结果：`legal_clear` / `method_failure` / `constraint_violation` / `assisted` / `unresolved` / `invalid_infrastructure`。
- 主目标、普通通关及特殊保护目标是否达成：待填。
- 原始结局证据与约束校验索引：待填。
- 人工介入、动作验证失败、失败阶段与原因：待填。
- 通关/主目标/违规/人工介入/方法失败/基础设施异常分别记录事实与发生顺序；按协议派生最终结果，不用后续断连覆盖已确认结局。
- 中间 `proposal_rejected` / `request_error` / 动作未生效与终止方法失败分别记录；预算内修正成功不自动导致整次失败。
- 无效判定的独立依据、是否与方法有关、是否补跑：待填。
- 判定者、日期、争议与敏感性分析分组：待填。

- 检测、修复提交、动作恢复的墙钟/游戏延迟：待填。
- `deviation_detected` 的发现主体、偏差类型、关联行动及证据 ID：待填；共享验证器发现与策略识别分开。R 另报 handoff 后的方法耗时。
- 是否直到终止仍未检测/修复/恢复，终止时刻：待填，不将未恢复耗时记为 0。
- 剩余节点数、有效保留数、参数/节点/边编辑、全局回退：待填；不可比较项说明原因。
- 模型不可精确计量的隐藏费用或 token：待填并注明来源限制。

## 材料位置

这里只存不含凭据和真实账号画面的索引/摘要。原始截图、视频、设备标识和运行目录保留在独立本地研究存储，不提交仓库。记录观察与动作不构成精确状态回放，也不能从录像得到另一方法的反事实通关结果。
