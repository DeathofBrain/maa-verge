## 要回答的问题

实际情况与原计划不一致时，Agent 能否找出需要调整的步骤，保留仍然可行的安排，并在已经采取的行动、剩余资源和时间限制下完成后续战斗？

1. **完整解题能力**：从统一关卡资料出发，生成的计划能否完成高难关卡？
2. **修复收益**：共享初始计划时，增量修复相对全量重规划能否降低恢复耗时和模型开销，同时保持或改善通关率？
3. **修复边界**：什么情况下局部调整足够，什么情况下应转向全量重规划？
4. **结构证据**：修复是否确实改变必要的决策依赖或子图，还是只修改了时间、目标和参数？

这些是待检验问题，不是已有结果。首版不预设 DAG 方法必然优于顺序计划或全量重规划。

## 两种图的含义

**关卡事件图**表示对敌人出现、阶段、机制触发和相关前提的理解。固定关卡脚本里的阶段切换可能完全可预知；后来观察到某个阶段，也可能只是补全了先前不知道的信息。记录时区分新信息、真实条件分支、时序或资源偏差、动作失败、感知错误。

**决策 DAG**表示当前有限规划窗口内的行动及其前置条件、因果支持和资源顺序。技能循环和撤退再部署通过带时间与发生次数的行动实例展开；外层“观察—规划—执行”可以循环，不要求整场战斗天然是 DAG。已执行动作及其费用、占用、冷却单独保留为不可回滚历史。

影响范围同时考虑图依赖和共享资源。例如两个没有直接因果边的节点，也可能争用同一个干员、部署位或费用。新增资源调度边与关卡机制依赖变化分别记录。

## 研究结论的边界

高难关卡首先提供有实际压力的长程任务。只有同时保存变化依据、必要依赖修改和后续执行证据，才能讨论决策结构修复；仅有动作延迟和遗漏实验时，结论应限定为执行偏差下的计划恢复。

如果要进一步主张“关卡事件图变化驱动决策 DAG 修复”，需要另行登记具有可核验条件分支的场景子集，证明事件模型的更新确实导致了必要决策依赖变化。首版候选中尚未核实的机制不能支撑这一主张。

公开关卡可能出现在模型预训练语料中。评测禁止运行时读取现成攻略与 Copilot，保留资料访问记录；这不能证明完全消除了模型已有记忆。留出集指未用于调参，不代表关卡名称保密。
