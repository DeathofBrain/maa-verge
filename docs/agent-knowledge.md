# Agent 数据集第一阶段

第一阶段提供可追溯的公共资源索引、产品能力与文档索引、设备账号范围内的识别快照。全部构建和查询均在本机完成。Agent 对话仍使用原有确定性提案；模型、向量检索、养成成本计算和自主战斗尚未接入。

Agent 相关功能、知识数据和后续模型编排在 `dev-agent` 分支独立开发；该分支由 `dev` 建立，本阶段数据集作为其初始能力。

## 数据来源与格式

| 来源                  | 规范记录                                         | 边界                                                                                    |
| --------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------- |
| `battle_data.json`    | 干员 ID、多语言名、职业、星级、范围 ID           | 只收 `char_` 身份，保留同名不同 ID；不是完整技能、数值及养成成本库                      |
| `item_index.json`     | 物品 ID、名称、用途、描述、分类                  | 不推断配方和当前库存                                                                    |
| `stages.json`         | 关卡 ID、编号、理智消耗、掉落种类关系            | 不包含掉落概率、样本数、统计时间窗；存在关卡记录不表示当前开放或 MaaCore 可导航         |
| `recruitment.json`    | 标签、可公招干员、星级与标签关系                 | 按所选客户端读取；实际公招计算继续复用工具箱                                            |
| `infrast.json`        | 设施、技能、别名、条件描述、原始效率值、干员关系 | `conditionsEvaluated: false`；不把条件技能直接相加为最优排班                            |
| JSON Schema、任务目录 | RPC 参数/返回值、可达定义、任务名、默认参数      | Schema 和任务登记不代表真实设备验收或执行授权；现有策略代码继续负责权限、参数与消耗校验 |
| 固定产品文档          | 按标题与有界段落分块                             | 保留说明和缺口，不将 PLAN 未来目标、STATUS 历史记录写成当前能力                         |

统一记录包含 `key/kind/id/name/aliases/text/data/relations/source`。`source` 保留相对文件名、JSON Pointer 或文档行位置以及 SHA-256；关系引用稳定 ID。原始下载文件不修改、不复制进 Git。模板图片、OCR/ONNX 和原生文件继续作为识别执行资产，不转换为文本向量。

公共资源仅从服务选定的不可变 generation 中读取五个固定 JSON；每文件最多 4 MiB，拒绝链接路径并限制记录与字段大小。官服/B 服共用基础文件；外服物品、公招、关卡和基建仅使用其对应目录，缺失时明确报告，不用国服记录补齐。多语言 `battle_data.json` 按客户端名称过滤。

资源包的指纹包括解析器版本、客户端、核心/资源版本以及各源文件的状态和哈希。未变化的源复用对应记录；文件缺失、损坏、解析器不兼容或缓存损坏时重新构建。改动解析语义应提升 `resourceKnowledgeParserVersion`。派生索引使用持有既有租约的 Store，缓存于 `knowledge_resources`，不另开业务数据库。

## 离线构建

先按项目开发流程准备固定 Bun 和工作区依赖。以下命令不启动桌面、本地服务、ADB、游戏、模型或联网下载：

```powershell
pnpm knowledge:generate
pnpm knowledge:check
pnpm knowledge:build --resource "<包含 resource 子目录的 generation>" --client Official --version "<已知资源版本>"
```

`knowledge:generate` 从 Schema、任务目录和固定文档生成随 Bun 编译的 `product-knowledge.generated.json`；变更来源后需要重新生成。`knowledge:check` 检查是否过期，项目检查与运行时打包也会执行此门禁。发行运行时无需读取仓库文档或加载 Schema 编译器。

`knowledge:build` 的默认输出为当前 checkout 的 `config/knowledge/<client>/`；可用 `--output "<目录>"` 修改。它生成：

- `resources-<fingerprint>.json`：规范化资源记录、来源清单和缺口。
- `product-<digest>.json`：产品能力与文档记录。
- `manifest.json`：当前文件引用、指纹、各类数量及缺口。

构建器校验旧索引后按源增量复用，先发布内容文件、最后切换清单，不覆盖仍被引用的旧内容文件。输出不得位于输入 generation 内。离线产物不包含账号数据或绝对源路径。当前不会自动下载新数据或自动清理旧导出；资源版本未知时保持为空，`--version` 是调用者提供的版本标签。

## 运行时查询

接口都通过 `packages/contracts` 的类型化 RPC 暴露，不接受文件路径、SQL 或任意命令：

| 方法                    | 参数                                            | 结果                                                   |
| ----------------------- | ----------------------------------------------- | ------------------------------------------------------ |
| `knowledge.status`      | 可选 `clientType`                               | 当前启用资源的指纹、来源状态、各类数量、产品指纹及缺口 |
| `knowledge.search`      | 可选 `clientType/kind/id/query/offset/limit`    | 有界记录列表、总数、分页位置、指纹                     |
| `account.snapshot.get`  | `deviceId/kind`；可选 `clientType/snapshotId`   | 当前快照或指定历史快照；无数据/范围不匹配返回 null     |
| `account.snapshot.list` | `deviceId`；可选 `clientType/kind/offset/limit` | 当前配置身份范围的历史摘要、当前引用和分页             |

`kind` 包括 `operator/item/stage/recruitment/infrastructure/document/capability`；账号快照类型为 `depot/operators`。知识检索优先精确 ID、名称和别名，再匹配关键词与中文子串；它不是语义向量检索。每页最多 50 条，同时将知识响应限制在 3 MiB 内；下一页使用 `offset + records.length`，不能假定始终返回请求的 limit 条。

查询资源索引不启动设备或任务；产品知识即使未安装 MaaCore 也可查询。当前开放时间和导航能力继续使用 `stages.list`，精确费用、公招和消耗规则继续使用本地工具。资料被检索到不等于系统可以执行相关动作。

## 账号快照与隐私

现有 `recognition.get`、工具箱和库存估算继续使用原有识别结果。新增历史在匹配当前任务的有效最终识别结果、任务成功及核心空闲全部满足后，与识别缓存同一事务保存；失败、停止、过期回调不更新历史。记录来自原始白名单识别字段，不使用展示名补全结果或掉落估算覆盖事实。

快照包含：身份范围哈希、设备、客户端、识别类型、采集时间、运行/工具 ID、任务位置、解析器版本、执行设备的核心/资源版本、已采集明细及未知字段。

- 身份始终包含设备和客户端。`configured-label` 只表示配置了账号标签，不代表识别或验证了游戏 UID；`device-only` 不与其他设备合并。游戏内手工换号无法自动检测，仍需显式启动账号配置并重新识别。
- 明细覆盖标记为 `partial`；仓库未出现物品不推定数量为零，缺失干员不推定未持有。未采集的技能、专精、模组、信赖显式标记未知；未知或无效练度转为 null。
- 首次读取原有识别缓存时可补入 `legacy-cache` 历史包装；历史核心/资源版本和任务位置保持 null，不套用当前组件版本。
- 成功换号清除当前引用和原识别缓存，保留历史。A → B → A 不自动把 A 的旧历史恢复成当前状态，须重新识别；显式历史查询受当前配置身份范围限制。
- 每个身份范围、每种识别类型保留最近 20 份，列表只返回摘要；账号范围数量没有全局磁盘配额。重复结果不重复追加。
- 账号快照保存在可配置业务数据根的 `native/maaverge.sqlite3` 中，默认开发目录为 `config/native/`；不进入公共知识包、默认事件日志或版本库。估算仍由独立 `inventory` 记录管理。

## 当前验证与下一步

自动验证使用隔离数据根、固定 Bun 与合成资源/回调，覆盖客户端隔离、哈希增量、损坏缓存重建、响应字节上限、成功与空闲证据、失败/停止保护、换号、历史去重/保留和重启。

已有公开资源可以用于离线提取核对，这不代表真实游戏采集、通关、最优排班或其他平台已验收。后续补充养成成本/合成配方、带版本/时间窗/样本量的掉落统计，以及可验证的基建条件规则，再接入目标规划和带来源的 Agent 问答；向量索引需单独固定模型与索引版本。
