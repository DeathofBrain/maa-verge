# 连接与开始唤醒的共享设置

设备页和开始唤醒任务共用连接设置，参考 [原版 MAA 连接文档](https://docs.maa.plus/zh-cn/manual/connection.html)。未配置多开实例时使用全局默认；选中已关联实例的设备时，只编辑该实例的连接和截图配置。开始唤醒的 `client_type`、是否启动游戏和账号切换仍属于任务参数；连接设备不会执行这些任务。

- `Settings.connection` 可选，旧设置保持默认链路。显式保存后包含 ADB 路径、常用连接地址、内置连接配置、触控模式、ADB Lite 和连接阶段的客户端。ADB 路径支持绝对路径、用户目录或 `adb`（自动查找 PATH/SDK 等来源），留空沿用环境变量、增强截图模拟器内置 ADB 与自动发现。Windows 还可从已运行模拟器的可执行文件位置定位内置 ADB，支持自定义安装盘和 MuMu `nx_main` 布局；显式坏路径会显示可读错误，便于修正配置。
- `Settings.capture` 保存 ADB/MuMu/雷电截图模式与 `autoDetect`，另有可选 `mumuTouch` 与 `mumuBridge`。截图协议默认「自动识别（推荐）」；在 Windows 上按已核实的模拟器实例、安装目录与本机 SDK 选择 MuMu 或雷电增强截图，其余设备使用 ADB。增强模式还需核心实际回调确认；缺失证据或回退到 ADB 将拒绝连接/执行。
- C++ worker 在 `AsstAsyncConnect` 前通过 `AsstSetInstanceOption` 设置 TouchMode=2、AdbLiteEnabled=4、KillAdbOnExit=5（固定关闭）和 ClientType=6。应用宝和 WSA 在连接阶段需要客户端包名，需与开始唤醒客户端保持一致。选择不受当前核心支持的选项会明确失败。
- worker 先加载基础资源，再按客户端加载 `resource/global/{YoStarEN|YoStarJP|YoStarKR|txwy}/resource`；官服与 B 服共用基础资源。外服覆盖目录缺失或加载失败时明确报错。任务需要切换客户端时，仅在该设备核心空闲后关闭旧 worker、释放租约，再用原有 ADB/触控/截图配置重建；连接和空闲确认完成后才提交任务。停止或退出会取消等待中的切换，其他设备继续独立处理。
- MuMu 触控增强通过连接 extras 的 `touch: true` 和触控模式 `MumuExtras` 传递，需要 Windows x64 官方 MuMu 6.3.2+。这是上游实验接口，核心可能回退 Minitouch；触控成功无法由截图证据证明，界面不宣称触控增强已验收。
- MuMu 桥接模式明确指定本机 SDK 实例号，允许手动 ADB 网络地址；通过 MuMuManager 确认安装目录与已启动实例后，设备租约映射到该实例的实际本地地址，防止桥接地址与本地串号绕过本应用的共享锁。无法确认实例时拒绝连接。自动发现只检查本机候选；桥接地址由用户手动连接并核对截图。
- 截图测试通过 `device.frame` 读取已连接设备的实际 PNG，展示尺寸、传输延迟和核心确认的截图协议；测试画面只保存在当前组件内存，不写入业务数据库。耗时包含截图、传输和后端校验，区别于原版仅比较截图方式的最优耗时。

## 自动识别与手动截图

自动识别会在每次连接时重新核对实例，成功后为该实例单独保存安装目录、实例编号、连接配置和截图协议，不把一个全局 SDK 编号套到全部多开实例。MuMu 使用管理器返回的实际地址；雷电必须同时取得 `ldconsole.exe list2` 的已启动实例信息，以及归属该实例进程的默认 ADB 监听端口，安装目录还需存在 `ldopengl64.dll`，才会自动提供增强截图配置。端口被其他进程占用或尚未就绪时会给出诊断，不把该端口上的设备当作雷电实例。

可在「截图协议」显式选择 **ADB 默认截图、MuMu 增强截图、雷电增强截图** 覆盖自动识别。手动增强截图可编辑目录与编号；自动识别后的目录和编号只读。旧配置没有 `autoDetect` 时，原 ADB 配置按自动识别处理，原 MuMu/雷电增强截图配置按手动处理，保留已有目录、编号和实验选项。明确选择 ADB 会保存 `autoDetect:false`，后续连接保持 ADB。

首次连接未识别出受支持的实例或 SDK 时使用普通 ADB；已经自动保存或手动选择的增强截图，在重新连接时无法确认实例、SDK 或实际增强接口便报错，不静默降级。可修复模拟器状态后重试，或明确改选 ADB。自动识别不启用 MuMu 实验触控或网络桥接，这两项仍需手动选择。配置变更用于下次连接，已连接设备需先停止任务、断开再重连。

## 模拟器多开

`Settings.deviceProfiles` 为可选实例清单（最多 32 项）。每项拥有独立 `id`、名称、地址、`connection` 与 `capture`。增强截图自动识别成功时生成带 `autoDetected:true` 的独立实例配置；用户编辑保存后转为手动管理，旧清单未标记来源时也按手动管理。手动新增实例使用空路径、截图自动识别和索引 0，不继承全局增强截图编号；需要手动增强截图时按多开管理器分别填写。

设备页可添加、编辑、单独连接、选择和删除实例。连接中的实例仍使用已加载的配置，编辑在断开后重连时生效；必须先断开才可删除配置。连接结果保存 `Device.connectionProfileId`，异步核心错误保存在该设备的 `connectionError`，每个实例卡片分别显示状态与原生错误。

没有实例清单，或清单全部由自动识别生成时，“自动连接模拟器”和后台自动连接继续发现新启动的本机实例。只要清单包含手动新增或编辑过的实例，就逐项尝试已保存清单，使用各项的 ADB、触控、截图 SDK 与实例编号，不自动连接清单外设备；单个实例失败不会阻止其余实例。“发现设备”始终可以单独检查本地候选，建立已监听端口的 ADB 传输连接后列出设备。

Windows MuMu 通过固定只读命令 `MuMuManager.exe info -v all` 枚举全部已启动实例的实际 ADB 地址、名称与编号，支持高索引、非默认端口和多个安装目录。雷电从运行进程定位安装目录，以固定 `ldconsole.exe list2` 查询已启动实例和截图 PID，核对默认 ADB 端口的进程归属后提供实例信息。查询失败时继续有限默认端口、现有设备与手动配置，不启动或关闭模拟器。完整发现顺序与查询限制见 [自动连接](emulator-connection.md)。

串号与回环 TCP 地址的 Android 标准别名会规范化，重复配置会拒绝保存；MuMu 结合管理器元数据及同一设备进程的监听端口确认实例别名，不能仅凭常用端口数字合并设备。同一实例的别名共享设备租约，不同 PID 或不同安装目录的多开实例独立识别；显式 MuMu 桥接实例也必须匹配同一本机实例。每个控制器使用独立 worker，设备租约位于共享用户目录，跨数据目录和工作树仍不能同时控制同一设备。独立进程和租约已用双 worker、合成 SDK 与原生租约测试验证；尚未执行真实模拟器多开游戏验收。

本功能不自动启动模拟器，不下载替换 ADB，不注册表查找安装目录，不提供任意启动命令或平台窗口连接。MaaFwAdb/AVD 依赖当前核心携带的控制单元。真实连接和增强截图实测限本机 Windows 单个 MuMu；雷电、真实多开、其他客户端及平台仍需分别验收，其他平台不能启用 Windows 增强接口。
