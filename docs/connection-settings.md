# 设备连接与游戏启动设置

本文描述 `feat/atomic` 当前源码。设备连接、任务执行、画面预览和原语 Debug 统一使用 MaaFramework，不加载 MaaCore，也没有双引擎切换。先在「设置 → 更新」安装并启用 MaaFramework 与游戏资源，再连接设备。独立安装说明见 [MaaFramework 组件](framework-updates.md)和[游戏资源](maacore-runtime.md)。

## 配置与连接

设备页分为「当前设备」「多开管理」「连接设置」。当前设备区分已连接、本次发现与默认折叠的历史连接；保存的实例或历史记录不代表设备在线。连接设置通过明确的配置选择器切换默认配置和各独立实例，不随顶部设备选择而修改另一份配置。

默认配置供没有独立配置的设备使用，多开实例使用各自的配置。当前表单提供 ADB 路径、连接地址、连接时的客户端及 MaaFramework 的截图／触控选项。参数保存在 `Settings.connection`，Framework 选项位于 `connection.framework`；每个 `Settings.deviceProfiles` 实例也有独立的 `connection.framework`。

ADB 路径可留空自动查找，或填写绝对路径、用户目录路径、`adb`。留空时沿用已配置环境变量和现有 ADB 发现规则；Windows 还可从已运行模拟器的可执行文件位置定位其内置 ADB，支持自定义安装盘和 MuMu `nx_main` 布局。显式坏路径会给出可读错误。应用不下载或替换 ADB。

连接设备只建立 Controller，不启动模拟器或游戏。「开始唤醒」只编辑游戏客户端、是否启动游戏和账号切换，并显示本表绑定或顶部所选设备的连接配置入口；保存任务参数不会写入设备设置。当前启动／关闭游戏只支持兼容矩阵已迁移的客户端和选项，其他配置可以保留编辑，执行前明确阻断，详见[功能兼容矩阵](maa-compatibility.md)。

连接成功后，同一设备持续持有一个 Framework Controller 和共享设备租约。画面、手动控制、任务及 Debug 复用该连接；手动、任务、工具和 Debug 的写入互斥，不另建第二个控制器抢占设备。修改配置用于下次连接，已有设备需先停止执行、结束控制会话、断开再重连；控制会话期间拒绝修改连接配置。

## 自动识别与手动截图

「MaaFramework 截图增强」默认**自动识别（推荐）**。连接时先核对本机 MuMu／雷电运行实例与截图 SDK；匹配成功才使用对应增强方案。其余设备保留普通 ADB 截图候选，并探测 AVD 增强接口。自动识别不会修改触控模式，也不把一个全局 SDK 编号用于全部多开实例。

可手动选择以下方式：

| 方式          | 条件与行为                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------------- |
| ADB 默认截图  | 使用 MaaFramework 的普通 ADB 截图候选，不启用模拟器截图增强。                                       |
| MuMu 增强截图 | 需要对应 Windows MuMu 的安装目录、实例编号和截图 SDK；连接前核对已运行实例。                        |
| 雷电增强截图  | 需要对应 Windows 雷电的安装目录、实例编号、`ldopengl64.dll`，以及可核对的实例 PID 与 ADB 端口归属。 |
| AVD 增强截图  | 需要模拟器提供 AVD 增强接口，不需要安装目录；手动模式无法确认接口或身份时失败。                     |

手动 MuMu／雷电配置不满足平台、目录、实例或 SDK 前提时明确报错，不改为另一种截图方式。自动模式没有可用增强候选时可使用 ADB；该候选选择不证明实际模拟器行为已验收。

AVD 以本机 TCP 地址连接时，先核对 QEMU 标记、设备的 AVD 名称及 console 返回名称。确认的 `emulator-*` 串号仅用于增强流的固定命令，Controller 地址和设备租约仍保持原身份；不能仅凭端口数字认定 AVD。自动核对失败保留普通候选，手动 AVD 身份无法确认时提示修正地址或改用自动截图。

## 触控模式

「MaaFramework 触控模式」默认 **MaaTouch**，另可选择 **Minitouch + ADB 按键、ADB Shell、模拟器增强触控（MuMu）**，对应固定 SDK 的四种输入实现。截图和触控分别配置，改变一项不会自动修改另一项。

MuMu 增强触控使用独立的安装目录与实例编号；目录留空时尝试核对当前设备对应的 MuMu 实例，可搭配普通 ADB 截图。若同时使用 MuMu 增强截图，两项必须指向同一安装目录及实例。雷电／AVD 截图不能与 MuMu 触控组合；自动模式未识别出 MuMu 时也不能据此启用 MuMu 增强触控。是否支持具体按键、导航及逐点动作，以当前 Framework 原生接口结果为准。

旧 MaaCore 的 `MaaFwAdb` 运行时下载与同版修复入口已移除。旧触控和截图配置在尚无 `framework` 配置时迁入新结构：已有明确 Framework 配置优先；支持的 `maatouch`、`minitouch`、`adb` 保留，旧专用触控选项采用 MaaTouch；旧截图仅在 `autoDetect:false` 时保留明确手动方式，否则使用自动截图。旧 ADB Lite、连接预设和实验字段不作为当前 Framework 执行选项继续提供，不会触发旧核心下载。

## 截图测试与预览

「截图测试」通过 `device.frame` 读取已连接 Controller 的实际 PNG，展示尺寸、总耗时和可用的截图方式信息。这里的总耗时由服务端计算，包含取得画面及 worker 通信，不含前端解码，不能当作旧 MaaCore `details.cost` 的纯截图指标；未提供具体方式时显示未提供，不据此宣称某个增强接口已经生效。正式 Pipeline 执行期间不能插入额外截图；界面已有画面仅供查看，不保证持续更新，也不代表可控制状态。

测试画面只保留在当前界面内存，不写入业务数据库。实时预览的往返延迟还包含前端解码，显示帧率按实际显示的新帧计算；目标刷新频率不保证设备达到对应 FPS。点击必须主动开启、设备空闲、画面新鲜且具有控制权；输入后原画面失效，未知结果不自动重放。

## 模拟器多开

`Settings.deviceProfiles` 最多保存 32 项，每项有独立 ID、名称、地址与连接配置。「多开管理」可添加、编辑、单独连接、断开、选择和删除实例，也可将发现的设备保存为实例。新增实例采用空 ADB 路径、自动截图及默认 MaaTouch，不复制全局增强截图编号。用户新增或编辑保存后按手动管理；执行、控制或连接操作未结束时，不能删除仍被引用的设备配置。

没有实例清单，或已有清单全部标为自动发现时，「自动连接模拟器」与后台自动连接继续发现新启动的本机实例。只要清单含手动新增或编辑的实例，就逐项使用已保存地址及各自配置，不自动连接清单外设备；单个失败不阻止其余实例。「发现设备」仍可独立检查本地候选，已监听端口建立 ADB 传输后才列出设备。自动重连保留退避、手动断开抑制和逐实例错误，保存清单不等于确认在线。

Windows MuMu 通过固定只读命令 `MuMuManager.exe info -v all` 枚举已启动实例的实际 ADB 地址、名称及编号，支持高索引、非默认端口和多个安装目录。雷电从运行进程定位安装目录，以固定 `ldconsole.exe list2` 查询已启动实例及截图 PID，并核对 ADB 端口的进程归属。查询失败时继续有限默认端口、现有设备及手动配置，不启动或关闭模拟器。发现顺序与查询限制见[自动连接](emulator-connection.md)。

Android 串号与回环 TCP 的标准别名会规范化，重复实例配置拒绝保存。MuMu 别名还需管理器元数据和进程监听证据，不能只按常用端口合并设备。每设备的原生进程持有共享用户数据目录下的设备租约；不同业务数据根、工作树和进程仍不能同时控制同一设备。稳定锁文件不会删除。

## 验证与历史边界

当前连接配置、自动识别、重连、互斥及协议通过隔离合成 SDK／原生 worker 夹具验证，不代表真实模拟器、游戏、多开和各平台已验收。本功能不自动启动模拟器、不使用注册表定位安装目录、不提供任意启动命令或平台窗口连接；MuMu／雷电增强接口限对应 Windows 模拟器。

迁移前文档曾记录 Windows 单个 MuMu 的真实连接与增强截图验证。该记录使用旧 MaaCore 路径，仅保留为历史，不能证明本次 MaaFramework 路径或其他宿主的真实表现。当前宿主与实际检查结果以[开发状态](STATUS.md)为准；上游说明可参考[原版 MAA 连接文档](https://docs.maa.plus/zh-cn/manual/connection.html)，其中旧核心选项不等于本分支支持项。
