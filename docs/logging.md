# 日志导出与清理

在「设置 → 数据与诊断」点击「导出日志」。完成弹窗显示完整目录和文件路径，生成的 UTF-8 `.log` 可直接交给开发者阅读。每次使用独立文件名，不覆盖先前导出；失败显示路径及原因，部分文件无法读取或超过限额时在弹窗和文件末尾注明。

| 环境           | 默认导出目录                                                                               |
| -------------- | ------------------------------------------------------------------------------------------ |
| Windows 安装版 | 主程序所在目录下的 `log`                                                                   |
| macOS 安装版   | `~/Library/Logs/Maa Verge`                                                                 |
| Linux 安装版   | `$XDG_STATE_HOME/maa-verge/log`，未配置或不是绝对路径时使用 `~/.local/state/maa-verge/log` |
| 开发与合成测试 | 隔离数据根下的 `native/log`                                                                |

`MAAVERGE_LOG_DIR` 可覆盖导出目录；安装目录不可写时明确报错，不请求提权或悄悄改位置。服务原始诊断始终保存在数据根的 `native/logs`，核心与工作进程日志保留在 `native/workers/<deviceId>`。

导出包含应用/Bun/系统与协议版本、时区、组件状态和生效路径、每实例实际使用的核心/ADB/连接/截图配置与连接状态、最近 50 次执行摘要、最近 1000 条事件摘要、服务和原生文本日志。服务诊断按 UTC 时间记录 RPC 方法、请求 ID、执行去重 ID、耗时、错误码与堆栈，保留事件的设备/运行/任务关联。正常截图轮询不逐帧记录。

导出不包含数据库文件、截图、模型设置或完整任务/账号结果；常见 API key、token、密码、Cookie、Authorization 和 URL 认证信息会脱敏。原生日志来自上游，仍应检查后再分享。日志是运行中的只读快照：最多读取 64 个文本文件，各取末尾 512 KiB，最终文件小于 8 MiB；截断及读取失败明确列在 `warnings`。服务日志每个进程每天最多 8 份、每份 2 MiB，达到上限暂停记录并在导出中注明。

自动清理默认保留 7 天，可改为 14 天、30 天或关闭。启动时检查一次，运行期间每 24 小时检查；保存新的保留期后立即按新设置检查。按文件最后修改时间清理过期服务/核心日志及本功能生成的历史导出文件。「清理日志」确认后清理所有可删除的日志，不受保留期限制，并显示删除数量、释放空间和跳过数量。

清理仅删除允许的日志文件名，不删除目录，不清除数据库中的事件或执行记录，也不处理截图、组件、锁文件及用户自行放置的导出目录文件。事件日志可在设备日志抽屉的显式选择模式中确认删除；该操作通过独立接口按事件 id 持久删除，不影响导出文件、执行记录或业务数据。当前服务正在写入的文件、本次服务会话启动过的所有 worker 目录都保留，包括已断开但可能仍在退出的 worker；这些历史文件在后续会话不再使用时才可清理。导出与清理在服务线程内串行处理，读取/删除前检查普通文件、链接祖先及文件身份，拒绝符号链接或 junction 导向其他目录。

类型化接口由 `packages/contracts/schemas` 定义：`logs.info({})` 返回目录及保留期，`logs.export({})` 返回路径/大小/提示，`logs.clean({})` 返回清理统计/提示，`logs.delete({ ids })` 按事件 id 持久删除 1–1000 条日志并返回删除数量；目录不能通过 RPC 任意指定。`Settings.logRetentionDays` 对旧配置可缺省。日志功能由 Bun 产品服务提供。

覆盖边界：服务初始化后的 RPC/事件与 `console.error`、已有 worker stderr 和 MaaCore 文本日志可导出；数据根无法打开等初始化前错误、Tauri 宿主/渲染层错误以及进程级崩溃转储尚未统一归档。macOS/Linux 的默认目录由合成测试覆盖，实际宿主权限与文件系统行为仍需目标平台验收。
