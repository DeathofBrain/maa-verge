# 主页游戏提醒与基建估算

主页按所选设备最近成功启动的客户端计算游戏日；没有记录时使用连接设置中的客户端，也可在提醒卡片中临时选择。官服、B 服和繁中为 UTC+8，日/韩服为 UTC+9，国际服为固定 UTC-7。每日 04:00 换日，周一 04:00 换周。周一提示安排剿灭，周日提示核对剩余合成玉；这只是日历提醒，不代表已识别游戏内周常完成情况。卡片中的开始、结束和预计满仓时刻以本机时间显示。

活动信息与关卡下拉共用类型化目录：参考原版 MAA 从官方 `StageActivityV2.json` 获取日历，使用 ETag / Last-Modified 条件请求和用户数据目录缓存，主源失败后尝试官方备用源。默认 6 小时重新校验；主页每分钟重算开放期，刷新按钮会主动重新校验官源。界面显示日历来源、最近检查、缓存待更新和请求错误。缺少有效官方缓存时才降级到已安装资源；不会修改正在使用的资源目录。

只有含可核验开放期且状态为 `active` 的活动显示“进行中”；联网失败沿用有效缓存时也按当前时间移除已结束活动。已安装资源只标记活动名、缺少开放期时，显示“资源标记活动 · 开放期未确认”，不把历史导航关卡推断为当前活动。日历不是游戏公告全集；只展示官方接口提供的活动与资源全开安排。

基建估算配置按设备 ID 保存在本机 Settings 的可选 `infrastructureEstimates` 中。初始为空。用户需要填写每条产线的名称、产出单位、每小时速率、容量和上次收取时间；服务从该次收取后的空仓开始计算 `min(容量, 速率 × 经过小时数)`。速率为 0 时不增长，未来的基准时间显示待校准。满仓提醒、数量和时间均为估算，不读取或控制游戏，不从任务完成回调推断收取成功。

干员加成、心情、订单、停工和手工收取会改变真实产量。收取后请在配置中手动更新时间，“我刚已收取，设为现在”只修改本机估算基准。配置或查看提醒不连接设备、不执行任务，也不发送通知或上传数据。

启动任务明确配置的账号标识或客户端与该设备上次成功启动记录不同时，只有任务成功且核心确认空闲后，服务才清除该设备的旧估算配置并提示重新校准；其他设备的配置保留。主页已打开的产线草稿也会随该设备配置失效而清空。未填写账号标识时，服务无法感知游戏中手工切换账号，用户必须自行删除旧产线或重新校准。

`home.info` 是只读 RPC，按设备和客户端返回当前游戏日、下次换日/换周、剿灭日历提醒、共享的活动关卡目录与服务计算的基建估算；界面每分钟刷新一次，切换设备后丢弃旧请求结果。
