# 作业中心接入与复刻计划

创建日期：2026-10-24。状态：**本轮功能已实现并通过合成与界面验证；实机验收待单独选择**。本文用于跨设备开发交接，接手者无需依赖原聊天记录。

本计划的范围选择优先于早期界面设计文档中“新作业可加入任务表”等冲突描述；架构、设备互斥、数据与验证规则继续遵循 [AGENTS.md](../AGENTS.md)、[PLAN.md](../PLAN.md) 和 [开发状态](STATUS.md)。

## 1. 已确认的目标与边界

- 按原 MAA 的执行能力复刻普通作业、保全派驻、悖论模拟、本地/社区导入、多作业队列、编队助战、独立执行及结果查看。
- 在应用内原生搜索、预览和导入 PRTS Plus 的作业与作业集，保留原站链接；首期不接入社区账号、收藏、点赞或发布。
- 作业库、队列和配置独立持久化，直接使用底层执行服务，不通过创建普通或隐藏任务表实现。
- 执行前选择设备，检查该设备是否有任务表、工具箱或其他控制者占用。同一设备忙碌时拒绝启动，其他空闲设备仍可独立运行。
- 启动后留在作业中心查看进度、日志、结果和停止操作；全局运行条、主页与执行记录同步显示状态。
- 新作业统一从作业中心创建和执行。旧任务表中的作业继续兼容，支持显式复制到独立作业库，不自动迁移或删除原配置。
- 视频识别留待后续独立离线流程；本轮也不包含作业编辑器、跨区域自动导航、云端模型或自主生成作业。
- 本轮新增范围集中在作业中心，工具箱沿用现有行为并共享设备占用规则。
- 社区服务与作业内容分别披露来源和权利归属，上传者与内容署名分开标注；原 JSON 导出附来源说明，不把下载内容自动视为本项目 AGPL 许可。详见 [作业来源与版权说明](copilot-attribution.md)。

## 3. 页面与用户流程

### 3.1 页面结构

- 提供「本地作业」「社区搜索」两个入口，以及当前类型的执行队列和详情区；普通、保全、悖论分开管理。
- 社区搜索切换「作业 / 作业集」，支持关键词、分页和编号定位；普通作业提供关卡筛选，默认按最新排序。
- 详情展示标题、作者、来源、关卡、说明、干员及技能/练度要求、最低核心版本，并提供原站和参考视频链接。
- 干员要求来自作业内容，不把要求展示等同于已确认当前账号满足要求，也不为浏览或导入自动触发设备识别。
- 沿用全局所选设备，在作业中心明确显示设备名称、连接及占用状态。浏览、搜索、导入和管理作业无需连接设备。
- 兼容浅深主题、窄窗、键盘操作和已有右键菜单；窄窗提供列表与详情的返回路径。

### 3.2 导入与队列

- 支持选择或拖入本地 JSON，以及粘贴编号、原站链接、`maa://12345`、`prts://12345`、`prts://s12345` 和 `s12345` 等代码。
- 导入后先查看解析结果，再加入执行队列；不能导入后自动开始游戏操作。
- 作业集保持上游顺序，展示各项解析结果；支持选择、排序、重复添加、删除和清除未勾选项。每次添加具有独立队列条目标识，不能只用社区作业 ID 定位重复项。
- 失效、已删除、内容无效或不兼容的条目明确显示原因，不静默跳过后开始执行；用户可以主动移除或取消勾选问题项。
- 普通单作业与多作业分别显示相应配置；保全只提供单份作业及循环；悖论提供单份或列表。三种类型不能在一个执行队列中混用。
- 队列与执行选项保存到本机；切页和重启后可恢复。修改正在运行的作业配置，只影响下次启动。

### 3.3 运行与兼容入口

- 开始后留在中心，展示当前条目、队列进度、日志、停止按钮及逐项结果。切页不停止运行，返回后恢复相应执行视图。
- 设备占用时说明当前运行，并提供查看入口；启动按钮的状态提示与服务端最终校验保持一致。
- 全局运行条、主页和执行记录包含作业运行；查看详情时按来源回到作业中心。任务表专用监控保留其归属语义，跨来源运行仍可从全局入口查看和停止。
- 任务添加器停止提供三类作业的新建入口；旧任务的编辑、保存和执行保持可用，并提供「复制到作业库」。本轮不改变旧视频任务的兼容路径。

## 4. 数据、公共接口与兼容设计

### 4.1 作业与文件版本

- 独立保存作业库、作业集来源与成员顺序、来源元数据、文件版本、执行队列和选项。队列条目引用确定的作业版本，允许同一版本重复出现。
- 在可配置数据根下建立作业目录；默认根继续遵循程序目录 `config` 的现有规则，不硬编码机器路径。
- 导入内容按哈希保存为不可变版本，保留原始作业 JSON 与来源；解析元数据不重写原始动作内容。重新导入或主动刷新产生新版本，不自动替换已选中的执行版本。
- 运行固定引用启动时文件、队列和配置的快照。删除库条目不得删除仍被队列、运行或历史记录引用的文件；不能覆盖活动 worker 正在使用的文件。
- 本地导入和社区导入经过相同的类型识别、格式检查、最低核心版本及已安装资源适配检查。无法识别或资源不支持时给出具体状态，不自动切换后端或开始执行。

### 4.2 RPC 与 Schema

- 新增作业/作业集搜索、详情解析、导入、列表、详情、删除、导出、工作区读取/保存和独立启动 RPC；参数与结果均由 Schema 定义并生成类型及独立校验器。
- 搜索返回展示摘要和分页信息，完整动作内容按需获取；完整作业 JSON 不加入全局快照。批量导入注意现有请求约 1 MiB、宿主响应行约 4 MiB 的边界，不能一次拼入无界内容或静默截断。
- 社区请求由 TypeScript 服务访问固定上游接口。React 通过 typed transport 调用业务能力，不直接执行 ADB、Shell 或 native 调用；链接导入先解析来源和编号，不把任意 URL 当作下载目标。
- 增加作业、版本、队列、工作区和运行来源类型。运行来源区分任务表与作业，并保存启动时显示名称；作业运行的 `planId` 可为空，旧记录缺少来源时按任务表解释。
- 运行详情增加作业队列条目的状态和结果，避免只显示一个外层 Copilot 任务而看不到内部执行位置。

### 4.3 共用执行服务

- 将任务表专属启动准备与通用执行分离：两类来源共用设备占用检查、运行登记、策略校验、原生提交、轮询、停止、事件及截图能力。
- 共用执行快照承载来源、任务和必要策略信息；作业启动不写入普通任务表对象。旧 `run_plan` 与历史运行继续可读。
- 复用 `run.stop`、运行详情及截图接口，所有运行都参与设备互斥、应用退出和应用/核心/资源更新门禁。
- 原生效果发生前，事务性持久化运行与请求去重。保留已有 `requestId` 记录；新请求按来源、设备和执行快照检查一致性，重复请求不能重复执行。
- SQLite 仍由 TypeScript 服务持有既有数据根租约后访问；C++ 不写业务库。新增对象或迁移不得删除锁文件、重建旧库或破坏隐式 rowid。

## 5. 原版执行语义与默认值

| 类型/能力 | 首期行为 |
| --- | --- |
| 普通单作业 | 使用 `Copilot.filename`，可设置循环次数 |
| 普通多作业 | 使用原生 `copilot_list`，保留地图导航、顺序、导航关卡覆盖和普通/突袭切换；不能拆成彼此独立的单文件任务来替代 |
| 保全派驻 | 使用 `SSSCopilot` 单文件及循环次数，不承诺多份保全自动串联 |
| 悖论模拟 | 使用专用 `ParadoxCopilot` 单文件或 `list`；对象列表携带整数条目标识，遵循固定版本核心契约 |
| 自动编队 | 普通作业提供编队栏位、追加干员、补充低信赖、忽略练度要求和助战设置；明确提示会清空当前编队 |
| 起始界面 | 单作业、地图多作业、保全和悖论分别显示上游要求；保全与悖论不套用普通自动编队 |
| 演习 | 沿用原版的游戏内选择方式，不以不存在的核心参数承诺自动切换 |
| 连续作战 | 遵循原版同区域限制，不提供跨区域自动导航；助战与循环组合遵循上游限制并给出提示 |
| 默认值 | 单次执行，关闭自动编队和助战；药剂、源石、加急额度保持零；无上限 `use_sanity_potion` 继续禁止 |

启动前，统一检查所选设备连接、活动运行、手动操作、worker 连接及 `safeIdle`、服务生命周期和更新切换状态。占用判定与运行登记必须防止并发请求越过检查；前端禁用按钮不能替代服务端控制权校验。

使用作业列表回调定位当前条目，结合 `taskid`、列表条目标识及启动快照隔离迟到消息。`CopilotListLoadTaskFileSuccess` 只表示作业文件已加载；`SubTaskCompleted`、`TaskChainCompleted`、`AllTasksCompleted` 和核心空闲分别处理，不能相互替代。

理智不足、战斗失败或非三星结算按原版停止后续队列，不自动重试。通关结果依据战斗反馈展示；证据不足时显示「未确认」，不能把文件加载或任务完成消息当作通关证明。任务链成功与核心空闲确认完成后，才能结束对应执行生命周期。

`AsstStop` 会清空原生队列，停止后保留本机配置和未执行项；再次运行需用户主动开始并重新核对现场。断线、崩溃和结果未知的操作不自动恢复或重放。

## 6. 作业站调研结果与接入依据

以下为 2026-10-24 的只读调研结果，说明可行性，不代表应用内功能已经实现或社区接口永久稳定。无需登录即可完成下面的检索与详情请求。

站点为 <https://prts.plus/>，其当前前端使用 API 基址 `https://prts.maa.plus`。

| 能力 | 已确认的接口 | 调研要点 |
| --- | --- | --- |
| 作业检索 | `GET /copilot/query` | `document=1-7` 能检索相关标题/说明；`levelKeyword=main_01-07` 能按内部关卡标识过滤。显示编号不能不经转换直接当作内部关卡标识 |
| 作业详情 | `GET /copilot/get/{id}` | 返回来源、类型及字符串化的 `content` JSON；导入时获取详情，不能把检索摘要视为完整可执行作业 |
| 作业集检索 | `POST /set/query` | JSON 查询体支持 `page`、`limit`、`keyword` 等；匿名名称搜索已实测可用 |
| 作业集详情 | `GET /set/get?id={id}` | 返回名称、说明及有序 `copilot_ids`，需继续解析各成员作业 |

接口均需检查 HTTP 状态、业务 `status_code` 和数据结构。作业集响应的 `data.page` 在调研中表现为总页数而非当前请求页；统一分页接口应保存请求页，并结合 `has_next`/`total` 处理，不直接将该字段用作当前页。

接入时对超时、网络错误、异常响应、删除/失效作业和部分导入失败提供明确反馈。搜索采用防抖并丢弃过时结果；社区失败不影响已导入的本地作业执行，也不自动刷新正在使用的版本。

## 7. 实施顺序与完成标准

按以下顺序推进，每一步都保持既有任务表执行可用：

1. **公共契约与独立存储**：定义作业、版本、工作区和运行来源；实现本地解析、导入、列表、详情、删除、导出与快照保护；生成契约并验证旧数据兼容。
2. **共用执行与设备互斥**：抽出来源无关的执行准备，接入三类作业和持久化去重；实现内部条目结果，覆盖与任务表、工具箱及手动操作的占用竞态。
3. **本地作业完整流程**：实现中心页面、队列、类型参数、启动、停止和结果；接入全局运行展示与来源跳转，保留旧任务表编辑及复制导入。
4. **社区检索与导入**：实现上游适配、关卡映射、分页、编号/链接解析、作业集成员预览与逐项失败反馈，将导入结果交给同一本地作业链路。
5. **回归与文档**：验证旧执行路径和新中心，更新开发状态、[功能兼容矩阵](maa-compatibility.md) 及 [界面设计计划](ui-redesign-plan.md)，修正早期文档中与本计划冲突的入口归属。

功能完成时，至少应能从空白作业库完成「搜索作业/作业集 → 预览导入 → 编辑队列与参数 → 选择空闲设备 → 独立执行 → 查看结果/停止」，且不会生成任务表；同时保持旧任务表执行与去重兼容。

## 8. 验证与跨设备交付

### 8.1 自动验证

- 后端合成测试覆盖三类参数映射、原生列表导航、重复条目定位、不可变文件引用、旧执行兼容、请求去重、设备占用竞态、停止、断线、迟到回调及缺少通关证据。
- 社区测试使用固定夹具和注入的 HTTP 适配器，覆盖分页字段差异、关卡标识转换、字符串化 JSON、失效内容、作业集部分失败、超时和异常响应。日常测试不依赖公网。
- 界面测试覆盖本地/社区导入、队列顺序与启停、重启恢复、忙碌设备拒绝、多设备并行、跨页停止、来源跳转、旧任务表兼容及自动保存/右键菜单回归。
- 检查浅深主题和窄窗，不出现横向溢出；运行中修改队列、切换设备或重新导入，不能改变当前运行的快照。
- 运行 `pnpm contracts:generate` 和 `pnpm contracts:check`；使用 `.bun-version` 与 `tools/setup-bun.mjs` 的固定运行时，完成 `pnpm check`、`pnpm test:runtime` 和相关 `pnpm test:e2e` 回归。涉及原生协议或打包时补对应检查。

自动验证使用隔离数据根、合成设备与 worker，关闭自动连接和组件下载，不连接真实游戏、调用付费模型或上传账号数据。真实设备验收必须另行显式选择并记录核心/资源版本；合成测试、浏览器测试和核心加载成功都不计为实机通关验证，未测试的平台不得标为已验证。

### 8.2 跨设备接手与交付记录

- 本计划需随 Git 提交或单独文件传递到接手设备；本地文件存在不代表已经提交、推送或远端可见。
- 从已同步的最新开发基线建立 `codex/` 功能分支；并行工作使用独立 worktree、数据根和端口，设备租约继续共享。
- 先确认规划时未提交的自动保存和菜单改动是否已经同步。不要复制整个工作目录、`config`、数据库、真实账号截图、下载缓存、虚拟环境或构建产物。
- 依赖、初始化与命令以仓库当前说明和根 `package.json` 为准，跨设备不使用原机器的盘符、用户名或 ADB 绝对路径。
- 提交使用 Conventional Commits，冒号后的说明使用简体中文。交付记录包含分支/提交、已完成范围、验证命令与结果、未验证平台、限制和剩余事项。

实现与验证记录以 [开发状态](STATUS.md) 为准；本轮不发布版本，不将合成验证视为真实游戏或三平台验收。
