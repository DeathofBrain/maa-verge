## Maa Verge v0.1.1

本次正式版带来多任务表监控、仓库与干员识别结果、应用签名更新和诊断日志，并完善组件下载、连接管理与数据保存。

> **升级前请留意**
>
> v0.1.0 用户需从本页手动下载并安装一次，之后才能使用应用内更新。请先完全退出旧版本并备份数据；本版默认将配置与历史记录保存到程序目录下的 `config/`，首次启动会尝试导入旧默认目录中的数据。
>
> Windows 安装包尚无 Authenticode 发布者签名；macOS 使用临时签名，尚未完成 Developer ID 签名与公证，系统可能显示安全提示。应用更新包的签名校验独立于系统发行签名。完整原 MAA 兼容与各平台真实游戏验收仍在推进，具体范围见下方限制。

### 本版亮点 | Highlights

#### 在一个页面关注各设备的执行

「任务表执行」默认打开监控总览，将运行中与最近结束的执行按卡片展示，支持筛选、搜索和单独停止。进入详情后可查看整次执行的任务结果、失败原因、累计材料与基建换班反馈，切换设备或其他执行时不会丢失当前查看位置。

#### 查看和导出仓库、干员识别结果

在工具箱选择空闲设备和客户端即可开始识别，成功后保存带采集时间的本机快照，支持搜索与 JSON 导出。仓库和执行掉落使用当前 MaaResource 中的材料图片与名称，基建反馈补充干员头像、星级和换班确认状态。

#### 分别更新应用与组件

Maa Verge 与 MaaCore 新增独立的正式版、预览版选择；应用更新经签名校验后，由用户确认在空闲时安装重启。组件下载提供跨页进度和失败重试，随包内置 aria2 1.37.0，支持核验分片后的断点续传，并可修复缺失或损坏的同版本组件。

#### 让数据位置和退出过程更清楚

配置、任务表与历史记录集中保存到程序目录下的 `config/`。设置中可导出诊断日志、调整自动清理周期；关闭窗口时可选择托盘或退出并记住偏好，完全退出时显示服务清理状态。

### 升级说明

1. **完全退出旧版本及其服务。** v0.1.0 没有应用更新器，需手动安装本版；Windows 建议继续使用原来的 EXE 或 MSI 安装方式，macOS 下载对应架构的 DMG，Linux 使用原分发方式更新。
2. **备份旧数据根。** 旧安装版默认位置见下表；如曾指定其他数据目录，请备份实际目录。退出后保留其中的数据库及可能存在的 WAL / SHM 文件、历史截图和其他业务数据。首次启动新版本后，先核对任务表、设备配置和历史记录，再处理旧备份。
3. **留意新的保存位置。** 本版默认使用程序目录下的 `config/native/maaverge.sqlite3`。仅在新库不存在且未显式指定数据根时，自动导入旧标准用户目录中的数据库与历史截图；已有新库不会被覆盖，旧文件继续保留。程序目录不可写时会明确报错，可通过 `MAAVERGE_DATA_DIR` 指定可写数据根，详见[数据迁移与备份说明](https://github.com/DeathofBrain/maa-verge/blob/v0.1.1/docs/runtime-migration.md)。
4. **保留仍被引用的组件目录。** 导入会保留原 MaaCore、资源和外部文件的绝对路径；请勿因数据迁移完成就删除旧组件目录。旧核心缺少完整性记录时，可能需要重新准备一次相同版本，验证完成并到达空闲边界后再启用。
5. **核对更新频道与下载器。** 应用默认选择「预览版」，MaaCore 默认选择「正式版」，可在「设置 → 更新」分别调整；选择正式版不会自动降级已安装的较高预览版。未配置下载器时使用包内 aria2，也可手动改用内置 HTTP。

| 系统 | 旧安装版默认业务目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\MAAVerge\native` |
| macOS | `~/Library/Application Support/MAAVerge/native` |
| Linux | `$XDG_DATA_HOME/MAAVerge/native`，未设置时为 `~/.local/share/MAAVerge/native` |

今后备份时，完全退出应用后复制整个 `config/`。单独备份它不包含另存于其他位置的组件、外部作业文件，以及由 WebView 管理的未保存草稿、最近选择和预览帧率偏好。恢复时保留原副本，不删除锁文件。

首次使用的用户可在安装启动后等待 MaaCore 和基础资源准备完成，再启动模拟器、开启 ADB，在「设备」页连接空闲实例，核对任务参数后手动开始。

### 已知问题与限制

* 定时调度、目标库存保持与自动补货、社区作业管理、跨执行掉落统计，以及原 MAA 的部分工具和外部服务尚未接入。仓库与干员结果为带时间的识别快照，不随游戏内变化实时更新。
* Agent 尚未接入云模型、视觉 Agent 或持续自主托管，当前仅提供本地规则提案，需审阅、保存后手动执行。公招加急、临期药和无限用药等选项仍受限。
* 真实连接与增强截图实测限已有 Windows 单个 MuMu。真实游戏任务、多开、雷电、外服及 macOS / Linux 的游戏操作仍待实机验收；macOS 最低系统、下载核心后的签名加载、Linux 托盘与干净系统交互安装也仍需目标机验收。
* 应用内安装支持 Windows EXE / MSI、macOS 对应架构应用与 Linux AppImage。DEB / RPM 需通过安装包或包管理器手动更新；应用目录不可写时仍需要安装器权限或改用可写位置。
* 应用更新包仅保存在本次会话内存中，退出后需重新下载，当前没有断点续传、aria2 下载或应用内版本回滚。组件下载继续使用独立的续传、版本保留和回滚机制；未完成分片的自动清理与磁盘配额尚未接入，aria2 当前固定单连接。
* 结果截图来自反馈后的核心缓存画面，可能已进入后续步骤，不能单独证明操作成功。旧执行记录不补造任务结果、干员信息或换班确认；新反馈中的方案指定名单也需核心确认，才会显示为已确认换班。
* 日志导出尚未统一归档服务初始化前错误、桌面渲染层错误和进程崩溃转储。常见凭据会脱敏，上游原生日志仍建议检查后再分享。

问题反馈：[提交 Issue](https://github.com/DeathofBrain/maa-verge/issues)，请附应用版本、系统、MaaCore / 资源版本、复现步骤与「设置 → 数据与诊断」导出的日志；分享前检查其中的个人信息。

### 新增 | New

#### 执行监控与识别结果

* 新增「监控总览」和「实例启动」视图。总览按每次执行展示任务表、设备、状态、进度、当前消息和耗时，区分正在执行与最近结束，支持状态筛选以及任务表、设备、结果搜索。
* 每张运行卡片可独立查看详情或停止；详情顶部保留其他执行的状态入口，同一任务表在不同设备上的执行分别呈现。
* 工具箱新增仓库与干员识别结果面板，可为所选空闲设备和客户端直接创建或复用快捷识别任务，查看物品数量、干员星级、精英化、等级和潜能，搜索名称 / ID 并导出 JSON。
* 识别结果按设备、客户端和类型保存在本机，显示采集时间。仅在最终有效回调、任务成功与核心空闲均得到确认后保存；失败、停止或不完整结果保留上次成功快照，确认换号后清除此设备旧缓存。
* 仓库与执行掉落新增材料图片，从当前启用的 MaaResource 读取对应客户端的名称和图片；资源启用或回滚后刷新，缺图保留名称并显示通用图标。
* 基建反馈新增干员头像与星级配色，从当前资源精确匹配姓名；同名多形态、缺图或资料不完整时保留可确认的信息，不猜测头像。

#### 应用更新与组件下载

* Maa Verge 新增应用签名更新，从本项目 GitHub Releases 读取发行版本；启动时默认只检查，由用户选择「下载更新」，验证完成后再确认「重启并安装」。
* 应用与 MaaCore 分别提供「正式版 / 预览版」频道并独立保存，应用默认预览版、核心默认正式版。预览频道同时包含正式发行，按有效 SemVer 选择最高版本，忽略草稿，不自动降级。
* 应用更新校验版本、平台、架构、安装方式、文件大小与绑定版本的签名；切换频道取消旧候选，检查失败清除不可下载候选，错误签名、安装器错配或版本回退均拒绝安装。
* 应用安装前确认所有任务、连接、原生调用及组件操作均已空闲，暂停新业务操作、关闭本地服务并释放占用后再调用安装器。Windows 保留 EXE / MSI 安装方式，macOS 使用对应架构更新归档，Linux AppImage 更新自身；DEB / RPM 显示手动更新提示。
* MaaCore / 游戏资源新增右上角常驻下载通知，跨页显示下载进度、解压校验与结果；失败可直接重试原候选，普通页面和设置操作继续可用，需共用更新队列的操作会等待完成。
* 随安装包内置 aria2 1.37.0，未配置下载器时默认使用，无需另装或配置 PATH，已有明确保存的 HTTP 等引擎选择继续保留。可切换到内置 HTTP，高级设置可指定 aria2 的绝对路径，保存后用于后续下载；留空只使用包内程序，缺失或运行失败明确报错。
* 两种组件下载器均支持核验后的断点续传，缓存按数据根、来源和版本隔离。HTTP 核对分片范围、服务端标记、大小与摘要，无法确认内容一致或来源不支持安全续传时重新下载；退出后保留可信分片，重新打开可重试。

#### 诊断与窗口行为

* 「设置 → 数据与诊断」新增单个 UTF-8 `.log` 导出，包含版本与环境、组件路径、每实例实际连接配置、近期执行与事件、服务及 MaaCore 文本日志，完成弹窗显示完整保存路径。
* 日志导出为常见密钥、token、密码、Cookie 和认证信息脱敏，限制读取与文件大小；读取失败或截断会明确提示，每次导出使用独立文件名。
* 新增日志自动清理，默认保留 7 天，可选 14 天、30 天或关闭；手动清理需确认，并显示删除数量、释放空间与跳过数量。当前服务及本次会话 worker 日志受保护，业务库、执行记录、截图、组件和锁文件不参与清理。
* 关闭窗口时可选择最小化到托盘、完全退出或取消，并可记住选择；设置中可改回「每次询问」。旧配置未明确记住行为时会重新询问，保存偏好失败时保留对话框和错误提示。
* 完全退出新增等待提示与转圈反馈，从托盘退出也会恢复窗口显示进度；重复退出共用一次清理过程，应用更新重启使用独立的安装退出流程。

### 改进 | Improved

#### 设备与任务表

* 「设备」页拆分为「当前设备」「多开管理」「连接设置」，分别显示已连接、正在连接、本次发现和折叠的历史设备，避免将历史记录当作当前在线设备。
* 发现的模拟器可保存为实例，在多开管理逐项连接、断开、编辑和删除；运行中、已连接或正在连接的实例限制冲突操作。
* 默认连接设置与实例独立设置的作用范围、下次连接生效规则更清楚；用户手动保存后不再保留自动探测标记。
* 「开始唤醒」任务专注于游戏启动、客户端和账号参数，显示任务表绑定或顶部所选设备，并提供设备设置直达入口。连接设备不会代替游戏唤醒，唤醒任务也不会启动模拟器。
* 日常与专项任务表的删除入口移到顶部工具栏，确认删除后选择同组可用任务表或显示空状态；执行历史继续保留，运行中的任务表仍禁止删除。

#### 执行详情与画面

* 执行详情集中展示整次执行的全部任务、失败原因、累计掉落和基建反馈，无需逐个任务切换才能查看结果。任务成功、失败使用整行颜色、图标与文字共同表达，长内容可滚动，改善窄窗与深色显示。
* 基建反馈区分方案指定、等待确认、核心已确认与旧记录未知状态，不再让方案名单看起来像已完成换班，也不推算未经确认的生产加成。
* 查看某次执行时，后台开始、设备切换、事件更新或其他执行结束不会抢走当前详情；返回总览保留滚动位置和查看按钮焦点，视图页签支持方向键、Home / End 导航。
* 任务结果截图默认折叠、按需读取；执行页面不持续请求实时画面，实时预览仍从底部「画面」手动打开。
* 持续预览改用及时释放的 Blob 图片，串行处理取帧、解码和绘制，减少逐帧图片校验与临时内存分配；统计每 250 毫秒更新。切帧、关闭、离线和卸载时释放图片，继续保留现有目标频率选项与实际 FPS / 延迟显示。
* 界面内置本地 Noto Sans SC 可变字体，标题、正文与表单离线可用；日志、路径和高级 JSON 保留西文等宽显示，中文使用同一黑体。
* 游戏提醒与关卡目录保留后台刷新前的内容，按设备和客户端隔离读取结果，切换上下文时及时清除不适用信息。

#### 数据保存与组件维护

* 默认数据根调整为程序目录下的 `config/`，集中保存设置、任务表、设备配置、执行历史、后续截图与服务数据；开发版各 checkout 使用自己的 `config/`，显式数据根设置继续有效。
* 首次在新默认位置启动且目标库不存在时，持有源、目标数据租约导入旧默认库和历史截图；一致性备份保留已提交数据、记录顺序与启动请求去重信息，校验失败拒绝创建空业务库。已有目标库不覆盖，源文件继续保留。
* 数据根不可写时明确报错，便于用户选择可写位置；组件及外部文件路径保持原值，界面未保存草稿和偏好继续由 WebView 单独管理。
* MaaCore 与独立资源分别默认保留三版，统计新旧安装根；优先保护活动、回滚、候选与 worker 使用中的目录，必要时暂时超过上限，空闲后继续维护，无法确认归属或删除失败时保守保留。
* 新快照记录展开文件清单与摘要，并在更新操作前流式复核，可发现模型、依赖等文件缺失、零字节、截断与同尺寸内容改写；旧核心无可信清单时提供同版本重新准备，始终写入新目录，原可用组合保留到验证和安全切换完成。
* 完整性复核发现候选被修改时拒绝启用；恢复损坏核心期间，继续保留最近有效回滚组合，不用失效的活动记录覆盖它。
* 下载归档暂存组件根目录，不再创建新的 `downloads/` 子目录；成功、失败或正常退出时清理临时归档与失败候选，可信的未完成分片继续保留以便续传。
* Windows EXE / MSI 完整卸载会清理程序同级默认 `MaaCore/`、`MaaResource/`，包含旧版目录布局；应用升级保留组件，自定义组件目录和用户业务数据继续保留。

### 修复 | Fix

#### 下载与组件恢复

* 修复 v0.1.0 的组件下载受整包两分钟总时限影响、持续传输仍被中断的问题，改为连接或传输停滞时才超时。
