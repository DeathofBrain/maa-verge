本次开发预览版完善作业库管理，统一应用、核心与资源的下载和代理，并支持保存应用更新包、下次启动时安装。

### 升级说明

1. v0.1.1 / v0.1.2 的 EXE、macOS 与 AppImage 用户可在「设置 → 更新」将 Maa Verge 频道切为「预览版」后获取本版；本版不再提供 MSI，旧 MSI 用户须备份后卸载旧版，再安装 EXE 或使用完整 ZIP。v0.1.0、ZIP 及 Linux DEB / RPM 用户须手动更新。
2. 安装前完全退出旧版本，备份整个 `config/`、已有作业 JSON 目录与自定义组件文件；数据位置见[迁移与备份说明](https://github.com/DeathofBrain/maa-verge/blob/v0.1.3-alpha1/docs/runtime-migration.md)。
3. 原下载器偏好不再使用，应用、MaaCore 和游戏资源统一使用内置 HTTP；如需指定代理，在「设置 → 更新 → 下载代理」中选择手动 HTTP/HTTPS 代理并保存。
4. 选择「下次启动时更新」后需真正退出并重新打开应用，最小化到托盘不会触发安装；作业 JSON 的新目录只用于后续导入，已有文件保持原位置。
5. ZIP 版不使用 EXE 自动更新，升级时请退出并备份 `config/` 与作业文件，再下载新版 ZIP；将备份还原到新目录后运行，不直接在压缩包中启动。

### 已知问题与限制

* Agent 仍只生成需要审阅、保存和手动执行的本地规则提案，云模型、持续托管、视觉自主操作及持久审批尚未开放。
* 作业干员标注依赖所选设备最近一次识别快照，绿色不代表技能、专精和模组等要求均已核验，缺失或未知数据需手动确认。
* 作业中心尚不支持社区账号、收藏 / 发布、作业编辑器及离线视频识别；普通多作业限同区域且整体单次，保全限单份，缺少明确战斗证据时仍显示通关未确认。
* MirrorChyan（Mirror酱）、纯 SOCKS / PAC 代理、下载缓存自动清理与应用内版本回滚尚未提供；VPN/TUN 继续依赖系统路由。
* 完整原 MAA 功能仍在补齐，真实游戏、多开、外服及 macOS / Linux 游戏操作仍需对应环境验收；macOS 首次打开可能需要在系统设置中放行，详见[安装说明](https://github.com/DeathofBrain/maa-verge/blob/v0.1.3-alpha1/docs/app-updates.md#macos-签名与首次放行)。

问题反馈：[提交 Issue](https://github.com/DeathofBrain/maa-verge/issues)，请提供应用版本、系统、MaaCore / 资源版本、复现步骤与脱敏诊断日志。

### 新增 | New

* 作业库新增分类管理与筛选，并支持单份、所选、分类内和全部作业的确认删除。
* 「设置 → 数据与诊断」新增作业 JSON 存放目录和删除偏好，默认保留应用副本与用户原始文件，执行队列和历史记录独立保留。

* 应用更新包通过签名验证后持久保存，可选择立即安装或下次启动时离线复核并安装，失败后继续启动旧版并保留手动重试入口。
* Windows EXE 新增 MaaCore 与 MaaResource 离线组件选项，并提供包含完整组件的免安装 ZIP。
* 新增独立 Agent 提案、工具授权与本机知识数据基础，产品对话继续使用本地规则提案。

### 改进 | Improved

* 作业集导入自动归入对应分类，并完善成员选择、批量入队、干员要求汇总与详情展示。
* 社区与本地作业展示声明的支持难度、干员要求和所选设备的持有练度，备选组可展开核对。
* 作业关卡按当前资源映射为易读编号，未知或歧义标识保留原值，原始 JSON 与导出内容保持不变。
* 移除 aria2，三条更新通道统一使用内置 HTTP、安全 Range 续传、完整性校验及有界重连，自动代理失败时尝试直连。
* Windows 停止提供 MSI 安装包，已有 MSI 安装需手动迁移。
* 优化组件完整性扫描，减少大资源目录检查对执行轮询的阻塞。
* 执行监控改为上方选择在线或历史设备、下方查看任务表、作业与工具，日志和连接设置统一从右侧打开。
* 首次启动在后台校验并准备随附组件，右上角显示进度，期间可继续浏览页面和编辑任务。

### 修复 | Fix

* 修复部分干员职业形态缺少详细记录时，其他有效持有记录被一并丢弃的问题。
* 修复后台组件请求较慢时应用更新安装准备受阻，以及准备取消后遗留状态的问题。
* 修复弹层切换后页面无法点击，以及迟到的启动响应覆盖当前设备和历史记录的问题。
