# Maa Verge UI 重设计计划

日期：2026-10-21。状态：**主页仪表盘与任务表工作台已实施**。默认入口按最新需求调整为主页，下述三栏编排保留为二级工作台；C–F 中尚缺的后端流程仍为后续目标。

本计划「样式统一」目标由 [组件套装](component-kit.md) 承载，本文不重复其组件清单与约定。

## 1. 设计结论与依据

采用以「主页」仪表盘为默认入口的桌面助手，展示今日执行/完成、连接设备、当前执行、最近记录和独立组件版本。主页不展示任务表卡片、任务表数量、新建或启动入口；从侧栏任务表进入完整编排工作台，调整每条任务设置；复杂选项按需展开。作业、长时间任务、工具和 Agent 使用适合各自内容的工作区。

用户已确认的要求：

- 优先照顾日常一键执行，复杂设置按需展开。
- 日常模式中包含任务表相关设置，用于执行日常任务。
- 侧边栏有任务入口、任务表列表及新增入口，每条任务都可设置。
- 减少明日方舟装饰；主页使用卡片仪表盘，任务编排保留三栏工作台。
- 侧栏指针悬停时背景平滑加深，选中态、按钮、卡片、页面和运行面板提供轻量过渡；尊重系统减少动态效果偏好。
- 以完整实现原 MAA 功能为目标，覆盖设置、数据工具与平台能力，而非只提供任务类型入口。

设计基线为官方 MAA v6.20.0。功能交付范围继续由 [原 MAA 功能覆盖与验收矩阵](maa-compatibility.md) 跟踪；本计划定义这些能力在界面中的位置和使用流程，不代表后端已实现。

### 当前结构需要解决的问题

1. 总览卡片突出设备与状态，却占用了编排任务和查看参数的主要空间；日常操作需要跨页面。
2. 大型任务编辑弹窗承载多条任务及大量参数，难以同时看到执行顺序与选中任务的完整设置。
3. 任务参数、设备参数、应用设置与更新缺少清晰的作用范围，后续增加定时、库存、排班会继续变长。
4. 识别、作业和库存保持是完整工作流，需要结果、缓存、导出及失败处理；只有“添加任务”和 JSON 不足以承载。

### 布局取舍

| 方向                           | 适用性                                         | 决策                               |
| ------------------------------ | ---------------------------------------------- | ---------------------------------- |
| 主页仪表盘 + 页内任务编辑      | 首页汇总状态与运行详情，复杂参数进入独立编排页 | 作为默认首页，保留完整页内工作台   |
| 所有任务与参数铺成一张长表     | 信息集中，但日常配置易被低频选项淹没           | 仅局部用于数据、作业与定时列表     |
| 导航 + 任务队列 + 选中任务设置 | 顺序、摘要、参数同时可见，适合反复编辑与执行   | 作为任务表列表与详情抽屉的基础结构 |

## 2. 导航与功能归属

主导航按使用目标组织，内部任务类型使用中文名称。顶部固定显示当前游戏档案、设备状态与全局搜索；底部固定运行状态。首次使用只创建隐式默认档案，单设备用户无需先理解多配置体系。

| 入口           | 主要内容                                                                                                                             | 页面形态                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| **主页**，默认 | 今日执行/完成、设备/运行统计、当前执行、最近记录、组件版本与作业/Agent/设置快捷入口                                                  | 状态仪表盘，不包含任务表管理                                                      |
| **任务**       | 任务表新建/复制/导入导出、设备绑定、勾选任务表后运行、单表与多表分别选择多台绑定设备启动；设备监控、批量停止、设备日志与单次执行详情 | 任务表列表 + 右侧详情抽屉（内嵌任务编排/任务表设置/定时计划）；设备监控为同页页签 |
| 作业中心       | 普通作业、保全派驻、悖论模拟、本地/社区导入、视频识别                                                                                | 可搜索列表 + 作业详情与执行要求                                                   |
| 工具箱         | 公招计算、仓库、干员、库存保持、数据更新、截图监控、小游戏                                                                           | 工具目录 + 操作区 + 持久结果                                                      |
| Agent          | 问答、计划审阅、托管、人工接管，研究入口                                                                                             | 对话 + 结构化计划/执行详情                                                        |
| 执行记录       | 运行结果、掉落、消耗、失败、关键画面与导出                                                                                           | 筛选列表 + 详情                                                                   |
| 设备，底部     | 自动发现、连接配置、诊断、平台驱动、画面/触控设置                                                                                    | 设备列表 + 分组设置                                                               |
| 设置，底部     | 通用、外观、模型、通知、外部服务、更新、数据与诊断                                                                                   | 分类索引 + 可搜索表单                                                             |

「任务」是唯一的任务表入口：列表展示任务数、绑定设备与最近执行，点击列表行在右侧抽屉内编辑并自动保存，不再按日常/专项分组或切换页面。全局搜索、主页快捷入口与 Agent 提案都定位到同一列表或抽屉。新建表统一写入日常组，旧专项表原样读取并显示在同一列表；不迁移数据，也不改 `Plan.group` 契约。列表支持勾选一张或多张任务表，页头「运行」仅在选中后启用：每张表均可选择多台设备，已绑定表限绑定范围，未绑定时临时选择。开始执行后停留在当前页并通过运行条反馈。重新加载默认回到主页，任务表与会话草稿通过「任务」重新打开。

定时属于任务表工作流。每张已保存表的定时页签支持编辑、添加和“查看全部定时”，全局选项在同一页设置；实现与边界见 [工具箱与定时计划](toolbox-schedules.md)。工具箱先选设备再检查占用，独立 ToolJob 不生成任务表，切页后执行继续；干员结果按 ID 读取资源头像。

### 设备执行监控与日志

- 从「任务」切到「执行监控」页签显示设备列表，每台设备一行；优先显示该设备正在执行的任务，否则显示最近一次执行或未运行。行内展示设备连接状态、任务表、状态、当前反馈、进度与耗时，并保留「详情」进入单次执行页。
- 支持按全部、执行中、空闲、离线筛选，并按设备名、地址、任务表与反馈搜索；列表排序将执行中设备置前。勾选设备后可只对所选设备批量停止，并可合并打开所选设备的日志。底部原「多开执行」入口继续保留。
- 设备日志抽屉先按设备筛选：设备复选支持单选或多选合并，全选只覆盖有日志的设备；日志行可逐条勾选，支持全选后复制或导出，最多展示所选设备最近 200 条并提示截断。关闭抽屉后焦点返回打开它的按钮。
- 查看单次执行时，顶部保留其他运行的状态条，可直接切换或返回「设备监控」。详情选择独立于顶栏设备与底部抽屉；任务结束、切换设备、打开日志或其他实例启动不会将详情跳到另一条记录。
- 监控仅使用执行摘要，只有查看详情才读取逐项结果；参考截图仍默认折叠，实时画面从底部按需打开。本机快照保留全部运行中执行及按创建顺序最近 100 条已结束记录；正在查看的记录被历史窗口移出后，详情仍独立读取最终结果。不扩展后端历史分页查询或调度能力。

## 3. 日常模式：核心页面

### 默认布局

以下是信息结构线框，非像素稿。屏幕整体只有三列：左侧导航、中间队列、右侧设置。任务表列表并入导航，运行区位于底部。

```text
┌──────────────────┬────────────────────────────────────────────────────────────┐
│ Maa Verge        │ 默认档案 ▾   设备：已连接 ▾                 搜索设置  ⌘/Ctrl K │
│                  ├────────────────────────────────────────────────────────────┤
│ ● 日常           │ 晚间日常   ⋯                   已保存     [开始日常 ▾]     │
│   我的任务表  ＋ │ [任务编排]   任务表设置   定时计划                          │
│   · 早间日常     ├───────────────────────┬────────────────────────────────────┤
│   · 晚间日常     │ 任务顺序     ＋添加任务│ 理智作战                           │
│   · 周常剿灭     │                       │ 关卡与目标                         │
│                  │ ☑ 1 启动游戏          │ 关卡        [1-7             ▾]    │
│ 专项任务         │ ☑ 2 基建换班          │ 执行次数    [6                ]    │
│ 作业中心         │     默认排班 · 5设施   │                                    │
│ 工具箱           │ ☑ 3 理智作战   ←选中  │ 消耗上限                           │
│ Agent            │     1-7 · 6次 · 零用药 │ 理智药      [0]    源石 [0]         │
│ 执行记录         │ ☑ 4 自动公招          │ 表级上限：理智药0 / 源石0           │
│                  │ ☑ 5 信用购物          │                                    │
│                  │ ☑ 6 领取奖励          │ ▸ 停止条件                         │
│                  │                       │ ▸ 掉落与数据汇报                   │
│ 设备             │                       │ ▸ 高级参数                         │
│ 设置             │ 本表：6项启用         │                                    │
├──────────────────┴───────────────────────┴────────────────────────────────────┤
│ 就绪 · 晚间日常 · 设备已连接                      运行详情 / 日志 / 画面  ▴    │
└───────────────────────────────────────────────────────────────────────────────┘
```

- 恢复上次任务表、选中任务、分栏宽度和展开状态；开始按钮始终在稳定位置。
- 左侧直接新建、命名、复制、分组及导入导出任务表。删除提供撤销；导入先预览客户端、任务、消耗和不支持字段。
- 添加器优先展示日常能力，支持搜索和分类；完整任务类型都有可发现的入口。模板中的启用项与消耗明示，可保存空表或全部禁用的表，但不能执行空队列。
- 队列行显示顺序、启用状态、中文任务名、两三个关键参数和运行状态。顺序编号表达实际执行顺序，不用装饰性序号。
- 支持同类多条任务、复制、拖动、按钮/键盘排序、多选及批量启停。关闭任务保留全部参数；JSON 中的有效启用状态与行开关保持一致。
- 点击任务直接在右侧编辑。普通参数不再放进大型模态框；小弹窗只用于命名、导入确认等短操作。
- 不选任务时，右侧显示任务表说明、设备、自动作战消耗汇总和最近一次结果；不堆叠大数字统计卡。

### 三个页签的职责

| 页签           | 用户可设置的内容                                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **任务编排**   | 添加、重复、复制、排序、启停任务；右侧编辑每条任务的独立参数                                                            |
| **任务表设置** | 名称与说明、游戏档案/客户端和设备绑定、自动作战消耗汇总、支持的任务默认值、失败策略、运行前后动作、通知覆盖值、导入导出 |
| **定时计划**   | 为本表增加多个触发器、启停与复制；查看下一次触发、设备冲突、强制触发语义、休眠恢复与最近结果                            |

日常用户在任务编排页即可完成“选表 → 开始日常”。修改整张表的行为无需去应用设置寻找；设备连接驱动等跨表配置仍归设备页，任务表设置提供直达链接和当前值摘要。

## 4. 复杂配置与保存规则

### 单任务设置

表单先显示目标与最常用选项，其余按语义分组展开。折叠项显示有效摘要，例如“停止条件：6次或目标达成”“高级：已修改2项”；有错误的分组自动展开。低频不等于永久隐藏。

| 示例     | 分组内容                                                                   |
| -------- | -------------------------------------------------------------------------- |
| 理智作战 | 关卡/次数/掉落目标；消耗；停止条件；倍率与代理；数据汇报；高级             |
| 基建换班 | 排班模式/方案；设施与执行顺序；心情与无人机；自定义排班文件/方案预览；高级 |
| 自动公招 | 星级与标签策略；招募次数与时限；确认/刷新/保留；加急与额度；高级           |
| 集成战略 | 主题与模式；队伍与策略；目标与停止；长时间运行限制；高级                   |
| 作业     | 来源/关卡/资源要求；作业队列；编队与助战；练习/突袭；消耗与重试；高级      |

较宽的表单使用清楚的标签列与控件列；相关选项并排，说明贴近字段。复杂排班、作业预览可临时放大设置区，保留返回选中任务的路径。

所有原版可用选项最终都有有名称、有说明、可检索的控件或等价编辑器。原始 JSON 仅作专家补充：保留未知字段、标注未映射字段、逐项校验；表单与 JSON 操作同一草稿，不产生互相覆盖的两份配置。

### 作用范围

| 范围         | 示例                                          | 用户如何辨认                           |
| ------------ | --------------------------------------------- | -------------------------------------- |
| 应用         | 外观、模型、通知服务、更新源、数据目录        | 设置页标题“应用设置”                   |
| 设备连接配置 | 连接地址、ADB、截图/触控方式、平台驱动        | 设备名称与配置摘要                     |
| 游戏档案     | 客户端、本地备注、库存/干员数据归属、默认设备 | 顶部档案选择；单账号默认隐藏管理复杂度 |
| 任务表       | 任务顺序、绑定、消耗汇总、失败策略与定时      | 任务表设置页；修改只影响该表           |
| 单任务       | 关卡、排班、星级、次数、任务自身消耗请求      | 任务设置标题和“使用默认/单独设置”      |
| 本次执行     | 仅本次跳过/启用、临时次数、临时设备           | “仅本次”标记及恢复入口；不写回表       |

不为每一层都复制全部设置。只有适合继承的字段支持“使用默认”，旁边显示实际来源和恢复默认。游戏消耗在「任务 → 任务表详情 → 任务编排 → 自动作战 → 消耗上限」逐项设置；本次执行上限由启用的自动作战任务累计，任务表设置仅显示汇总。新任务默认药、石均为零，加急与未审计的无限用药继续禁止。

Agent 的模型调用次数/费用默认值在「设置 → 模型与 Agent」，每次托管显示其有效预算；模型费用与游戏消耗分开表达，Agent 调整自动作战消耗上限的提案必须经过用户审阅。

切换当前浏览设备不改写任务表绑定，不重定向正在执行的任务。跨档案的数据不混合；切换档案时任务表保留绑定，跨档案执行须显式选择。设置搜索结果同时显示字段位置与作用范围。

### 草稿、保存与执行

1. 编辑即时进入本地草稿，停止输入 600ms 后自动保存；显示等待、保存中、已保存和失败状态，支持 ⌘/Ctrl S 立即保存。切换页面提交有效改动；无效字段与保存失败保留草稿，可修正或重试。Agent 提案首次保存仍须明确确认。
2. 点击开始先等待并保存当前有效配置，再执行；保存失败或参数无效则阻止执行。运行中编辑自动保存为下次执行的配置，不改变当前执行快照。
3. “仅本次跳过/启用”等从开始按钮的执行选项或任务菜单设置，与持久开关区分。运行前能看到覆盖汇总；退出本次执行上下文即清除，不影响定时任务。
4. 执行以固定快照记录任务表版本、设备、有效参数、自动作战消耗上限和一次性覆盖。运行中可以编辑、保存下一次配置，提示“当前执行使用启动时配置”。
5. 后续补齐原版运行中调整能力时，仅白名单字段可通过“应用到待执行任务”显式提交，显示差异与结果；不声称能任意修改正在执行的 MaaCore 任务。
6. 停止按钮文案为“停止执行”。停止清空核心队列，保留保存的任务表；重新执行要重新观察设备并创建新运行，不展示无法兑现的暂停/原地续跑。

## 5. 运行与异常反馈

运行条在所有页面可见，默认高约 44px，显示任务表、设备、当前任务、进度/耗时及停止入口。展开后是可调整高度的“进度 / 日志 / 画面 / 结果”区域，不永久挤占设置空间。

- 任务行区分等待、执行中、成功、失败、已跳过、已中断、结果待核对。当前运行结果与正在编辑的下一次草稿分别标识。
- 只有明确完成证据才能显示成功；队列结束不自动标为全成功。无可靠进度时显示阶段与耗时，不虚构百分比。
- 失败就地给出原因、受影响任务和下一步，例如打开连接诊断、修改参数、查看资源状态、核对游戏画面；重试注明范围。结果未知的消耗行为不能一键盲目重放。
- 预览画面默认按需打开，标注设备、采集时间与过期状态；模拟数据明确标为模拟。截图导出与记录按档案归属。
- 更新等待空闲、设备被占用、断线、资源不支持关卡等，分别展示可操作状态。多设备运行可从运行条切换查看，但对每台设备明确唯一控制者。

## 6. 配套工作区

### 设备与首次使用

首次启动完成组件安装后自动发现已运行的本地模拟器；只有一个合适候选时连接，多个候选时让用户选择并记住连接配置。顶部显示未连接、发现中、连接中、已连接、失败、被占用，提供取消和诊断。

连接成功不等于启动游戏或开始任务。启动模拟器、启动游戏是分别可配置的动作；手动断开后保持断开，直到用户重新连接或明确恢复自动连接。设备页保留手动地址、非标准安装路径、驱动选择、截图/触控测试与原版平台专用入口。尚未实现的平台路径按状态呈现，不提供可点击却无效果的控件。

### 定时计划

表格列出启用、时间/周期、任务表、档案、设备、下一次触发和最近结果；详情配置时区、运行冲突、强制触发及休眠恢复。至少承载原版八组定时及每组配置，数据结构不把八组作为产品上限。

默认设备忙时不打断正在执行的任务；强制启动必须说明是否停止现有执行、需要的权限及后续行为。休眠恢复按规则合并过期的周期触发，不补跑多份相同日常；停止/失败/错过各有记录。运行前后系统动作与用户手工脚本单独配置，不进入模型工具表。应用退出、托盘和系统休眠对调度的影响写在对应设置旁。

### 作业中心

用列表/表格显示名称、关卡、类型、来源、要求、更新时间和校验状态。支持本地文件、社区编号/链接及作业列表导入，导入后先预览。普通、保全和悖论使用匹配各自语义的表单，不强塞进一个通用文件选择器。

右侧详情显示干员/练度要求、兼容性、编队、助战和开始位置；三类队列独立保存并选择空闲设备执行，不创建任务表。作业版本与本次执行绑定，运行中编辑不替换正在使用的文件；旧任务表作业可继续编辑、执行并显式复制到库。视频识别的独立离线输入、进度、结果及导出仍为后续目标。

### 工具箱与数据

工具页面遵循“输入 → 执行 → 结果 → 导出/转为任务”。仓库和干员结果使用可筛选表格，始终展示客户端/档案、来源、采集时间、完整程度；外部只读数据导入与游戏内扫描分开命名，默认不上传。

库存保持展示目标库存、缓存数量、缺口、优先级、可用关卡与数据时间；用户可调整补货顺序并生成/引用作战配置。扫描失败或缓存过期时保留旧值并标为旧数据，明确是否刷新后重新计算，不把旧缓存当实时库存。公招计算提供标签输入、组合和星级结果；“只计算”和“自动招募”分离。数据刷新、活动、公招、掉落统计及导出拥有独立状态和错误反馈。

### Agent

保留独立工作区，承载问答、结构化提案、托管范围、预算和接管。任务页可通过“让 Agent 调整这张表”携带上下文，使用临时抽屉或替换设置区，不永久添加第四列。

Agent 产物进入同一任务表草稿，先显示参数/消耗差异，再按模式审阅与执行；不会维护另一套“聊天任务”。模型离线时日常表单与已确认任务仍可运行。研究能力与稳定功能分开标明。

### 设置与全局搜索

```text
┌──────────────┬──────────────────┬─────────────────────────────────────────┐
│ 全局导航     │ 设置分类         │ 搜索：通知                              │
│              │ 通用与外观       │ 通知                                    │
│              │ 模型与 Agent     │ 运行结束时通知       [开]               │
│              │ 通知与远控       │ 失败时通知           [开]               │
│              │ 外部服务         │ 推送渠道             [管理渠道]         │
│              │ 更新             │ 测试通知             [发送测试]         │
│              │ 数据与诊断       │                                         │
│              │ 关于             │ 适用范围：应用；任务表可单独覆盖         │
└──────────────┴──────────────────┴─────────────────────────────────────────┘
```

设置页用分类索引和连续表单，支持锚点与搜索结果直达。搜索覆盖应用设置、任务字段、设备参数和工具；结果标明所属位置，跳转时不丢草稿。更新页将应用、核心、资源列为三个独立区域，区分下载完成、验证通过、等待空闲、已生效，提供来源、检查时间、手动导入和可用回滚。核心版本相同不隐藏资源更新。

## 7. 视觉与桌面适配

视觉方向是清晰、安静的桌面工具：以任务顺序和参数摘要建立辨识度，减少卡片套卡片、巨大圆角、渐变背景与装饰图。游戏名称只用于表达真实功能、关卡与模式；不使用角色立绘、阵营标志或角色称呼。

| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

### 宽度与可访问性

- 以 1440×900 为主要设计尺寸，1280×800 保持完整日常工作流。导航约208–224px，任务列约280–320px，设置区优先保证约560px以上；实际按窗口内宽、边距和缩放计算。
- 分栏可拖动，设合理最小宽度并记忆。设置分类页可使用不同分栏比例，不机械复用任务队列宽度。
- 约1100px以下先收窄/折叠导航，再将队列与任务详情改成可返回的两级页面；不在普通桌面宽度突然变成一屏一张大卡。
- 更窄窗口用“任务列表 → 单任务设置”路径，保留返回、保存与开始/停止；表格横向滚动并保留关键列。390px仅作为降级可用性检查，不作为桌面布局主导。
- 支持键盘遍历、明显焦点、任务排序替代按钮、标签关联、错误聚焦、文本缩放及读屏状态；正文和控件按实际主题校验对比度。

本轮用文字线框即可评估结构，不需要生图。后续若进行视觉探索，遵从用户指定的现有 `.codex` 接入配置与 `gpt-image-2.5-flare` 模型；凭据不写入文档或仓库，图片只作视觉参考，交互与中文排版以真实原型验证。

## 8. 实施顺序与验收

以下为分阶段实施路线。A 的六张示意图已确认，B 工作台已落地并通过 23 项浏览器 mock 端到端测试；配套页面提供现有能力与明确的未接入状态，C–F 按功能矩阵继续推进。

| 阶段                  | 交付                                                                                     | 完成标准                                                                               |
| --------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| A：关键页面原型       | 日常任务编排、复杂作战、基建排班、作业中心、设置搜索五张页面；含表级设置线框、明暗与窄窗 | 使用真实中文字段验证信息密度、长内容、错误与键盘路径，确定布局后再扩展                 |
| B：日常工作台落地     | 导航、任务表树、新建/复制、页内任务编辑、任务表设置、草稿/保存、常驻运行条、设备摘要     | 现有任务与字段无损迁移；重复/禁用/排序/未知参数仍保留；一键执行与停止正确              |
| C：完整日常与调度     | 补齐原版任务表单、排班管理、多配置/档案、仅本次覆盖、定时、前后动作与通知                | 支持至少原版八组定时、配置绑定、休眠恢复、冲突和失败策略；受限消耗有确定性约束后再开放 |

| E：专项、平台与 Agent | 专项完整表单、平台连接/诊断、运行中参数调整、Agent 提案/托管、远控与外部服务             | 与同一任务、权限和执行服务集成；按原版功能矩阵逐项关闭差距                             |
| F：完整验收           | 三平台适配、主题、键盘/缩放、升级迁移、真实核心/资源组合与各客户端                       | 真实验证逐项记证据；mock、UI入口或平台CI不替代原 MAA 等价验收                          |

### 功能覆盖台账

实施前将现有兼容矩阵细化到原版设置项与工作流，至少记录“上游名称/固定版本依据 → Maa Verge入口 → 表单或等价编辑器 → 契约与后端能力 → 结果/失败反馈 → mock用例 → 目标平台实测”。标记已实现、受限、待实现和平台不适用，并说明等价路径。

该台账包含各任务扩展参数及原版UI自有流程；新增上游版本时核对差异。未映射或仅JSON可填写的功能不能直接标为完成。只有全部适用项具有可用交互、执行与结果证据后，才将“完整替代原版”列为已交付。

### 关键场景检查

1. 已配置用户打开应用，直接看到上次日常表；无草稿冲突时只需一次点击开始。
2. 新建晚间日常，加入两条不同关卡作战任务，分别设置、排序、关闭一条并重启，配置完整保留。
3. 在任务表设置找到设备绑定、消耗汇总与前后动作设置，在自动作战任务中调整具体消耗上限；参数错误定位到具体任务。
4. 设置仅本次跳过，执行结束后保存表不变；定时继续使用持久配置。
5. 运行中修改并保存下一次配置，当前运行快照不变；停止后不出现虚假的暂停续跑。
6. 断线、核心拒绝参数、资源过期、任务结果不明都显示可行动的错误，而非队列结束就显示成功。
7. 在仓库工具识别并导出，看到采集时间；旧缓存参与库存保持时显示来源与刷新策略。
8. 导入三种作业，能看要求、编队与开始条件；离线视频无需设备即可走完整流程。
9. 搜索“无人机”“强制启动”“资源更新”可直达正确位置，并看见作用范围。
10. 1280px下长任务名、二十条任务、较多选项与中文错误文本不挤压操作；键盘和明暗主题均可用。

### 当前实现与提案边界

- **已有基础**：任务表持久化、19类任务的常用字段/高级JSON、重复/启停/排序、自动发现与连接、运行/停止、记录、更新及mock路径。
- **本轮已落地**：日常/专项三列工作台、说明/分组/绑定/消耗汇总的任务表设置、自动作战单项消耗上限、分组表单、会话草稿与自动保存、开始前保存当前配置、分类设置与任务字段搜索、常驻运行/日志/停止栏、设备页和独立作业中心（本地/社区作业及作业集预览、不可变库、三类队列、设备检查、运行结果及旧配置复制）。六类独立工具、识别结果与库存补货、每日定时及 Windows 可选唤醒已接入，详见[工具箱与定时计划](toolbox-schedules.md)。任务表树、任务队列、设备/多开实例、执行卡片/记录与作业行提供右键菜单，复用已有编辑、连接和执行操作；空白区域与普通导航不显示菜单，输入框保留系统文本菜单。
- **后续目标**：任务表导入、空表、多选批量、分栏拖动/密度选择、运行任务的仅本次覆盖、完整档案、失败策略/完成动作、社区账号及作业编辑器、离线视频、完整 Agent 工作流。工具和定时的真实设备、实际休眠唤醒及各平台桌面行为仍按功能矩阵验收。
- **仍需按功能矩阵验收**：全部原版选项、当前受限消耗、自定义流程、各平台连接、六种客户端与真实游戏行为。仅做UI不能单独满足完整兼容目标。
- 后续接口变动同步更新 `packages/contracts`、TypeScript 持久化/校验与文档；React 继续通过类型化传输访问能力。历史数据迁移、执行快照与设备独占等架构约束保持有效。
