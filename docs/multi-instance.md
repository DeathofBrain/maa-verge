# 模拟器多开

Maa Verge 可同时连接多个模拟器实例，并为每个设备保留独立的 MaaCore 工作进程、执行快照、进度、停止请求、识别时间和本机设备租约。此能力在单个 Maa Verge 窗口内使用，无需为每个模拟器另开一份应用。

## 使用方法

1. 在模拟器的多开管理器中启动所需实例，并开启 ADB。
2. 在「设备 → 当前设备」点击「发现设备」，检查「本次发现」中的各已启动实例。已连接设备单独列出；历史连接默认折叠，不表示设备仍在运行。可把发现的设备「保存为多开实例」，或通过页首「管理多开」进入「多开管理」手动添加、编辑、连接或断开实例。截图协议默认「自动识别（推荐）」；Windows MuMu 从管理器读取实际 ADB 端口、名称和编号，支持高索引、非默认端口及多个安装目录，雷电结合 `list2` 与实例所属的 ADB 监听端口核实设备。连接时 SDK 与实例核实后自动保存独立截图配置，填写对应目录和编号。需要自定义时在「连接设置」明确选择要编辑的实例，手动选择 ADB 或增强截图；MuMu、雷电增强截图必须使用各实例对应的编号，也可为不同实例选择不同安装目录和 ADB。
3. 连接各实例，在「任务表执行 → 实例启动」中分别选择任务表并开始，底部「多开执行」也保留同一入口。切回「监控总览」可同时查看各任务表与设备的执行进度、当前反馈及失败结果，并单独停止；同一任务表在不同实例执行会分别显示。
4. 从卡片「查看详情」进入逐任务结果、材料与基建反馈。顶部保留其他运行的状态与切换入口；点击「返回监控总览」重新并排查看。停止、完成和失败的记录会保留在最近结束分区，可筛选或搜索。

没有实例清单，或清单全部由自动识别生成时，自动连接继续发现新启动的本机实例。只要包含手动新增或编辑过的实例，自动连接就限定在已保存清单内逐项尝试，失败单独显示并继续其他项。单独“发现设备”始终可检查本机候选，连接已监听端口的 ADB 传输后刷新列表，不启动游戏或任务。Windows 自定义安装目录可从已运行模拟器的进程路径定位内置 ADB，无需为每个实例安装一份 platform-tools；未识别的安装布局仍可手动选择 ADB。

自动连接开关位于「连接设置」，手动清单启用时的连接按钮显示「连接已保存实例」。任务表中的开始唤醒只负责游戏客户端与账号操作，设备连接设置统一从设备页修改；从任务页可以直达绑定设备的配置，未绑定时定位顶部所选设备。

同一张**未绑定设备**的任务表可以在不同实例同时执行。也可以复制任务表、分别绑定设备，保存不同账号的关卡、任务、预算与客户端。已绑定的表只会出现在对应实例的可执行选项中。编辑器顶部切换到另一个空闲设备后，也可启动同一张未绑定任务表。

## 配置与隔离

- 全局连接设置继续作为没有独立配置的设备的默认值。独立实例配置持久化在本机 `Settings.deviceProfiles`，按标准化地址选择对应连接/截图配置，不把全局增强截图编号套到所有实例。自动识别生成的配置带 `autoDetected:true`，用户编辑保存后转为手动管理；截图是否自动识别由独立的 `capture.autoDetect` 决定。旧 ADB 配置未指定该字段时按自动识别处理，旧显式增强截图配置保持手动。
- MuMu、雷电自动增强截图只针对已核实实例和存在本机 SDK 的 Windows 安装，雷电还要求默认 ADB 端口归属 `list2` 报告的实例进程。每次连接重新核对，已配置的增强接口失败会明确报错，不静默降级；需要普通截图时可显式改选 ADB。
- 每个实例只允许一个活动执行和一个控制者。同一 ADB serial、已确认的端口别名或同一 MuMu SDK 实例的桥接别名共享租约，不能用不同显示名称绕过排他控制。MuMu 通过管理器元数据与同一 MuMuNxDevice PID 的监听端口确认别名，发现列表只保留该实例一项；不同 PID 的多开设备独立保留，不把普通 `16384`、`5555`、`7555` 端口全局视为同一设备。设备租约跨开发工作树和数据根共享。
- 多实例可同时提交同一任务表；每次启动单独保存参数快照和请求去重键，之后修改任务表不会改动已在执行的实例。
- 停止只发送到对应实例的 worker；其他实例继续。回调即使具有相同的原生任务 ID，也只影响其来源设备的当前执行。
- 不同客户端的基础/外服覆盖资源分别加载在各自进程中；外服覆盖缺失或加载失败会阻止连接。任务切换客户端时只在目标设备空闲后重建其 worker，保留连接时的 ADB、触控、SDK 和实例编号；其他设备的执行与停止不等待该次重连。停止或退出可取消尚未完成的切换。
- 消耗上限按**每次执行**分别检查，默认均为 0；在多个实例上重复执行带消耗的任务表，会分别使用各次授权额度。
- 执行页独立保留主动查看的记录，切换顶部设备、打开底部日志或后台启动另一实例不会切走详情。底部运行详情仍跟随顶部设备的活动执行，截图与人工点击也按顶部所选设备定位；查看某次执行会同时选中其设备。

## 当前边界

目前管理的是已经启动、可通过 ADB 访问的模拟器实例；Maa Verge 不自动创建或启停模拟器。自动发现只检查管理器元数据、有限默认端口或配置提供的本机回环候选，不扫描端口范围。MuMu 管理器不可用时保留诊断并继续其余发现路径；其他地址可手动配置。增强截图按管理器实际端口优先核对 SDK 实例，不以简单端口等差公式推断全部多开实例。

核心和资源热更新仍等待所有活动设备到达安全边界，然后切换各 worker；不支持战斗中迁移上下文，也不提供逐设备滚动换核。

多开本身不要求 Windows 增强截图，普通 ADB 路径适用于 Windows/macOS/Linux。MuMu/雷电增强接口仍受 Windows、SDK、版本和实例编号限制。开发验证使用隔离的合成设备与 worker；本次发现修复只在一个 Windows MuMu 实例上实测，真实多开模拟器、不同客户端及其他平台仍需分别验收，不能把合成通过视为账号操作已验证。
