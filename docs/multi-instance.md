# 模拟器多开

Maa Verge 可同时连接多个模拟器实例，每个设备使用独立的 MaaFramework 原生工作进程与常驻 Controller，保留各自的执行快照、进度、停止请求、识别时间和共享设备租约。任务、工具、画面与 Debug 复用该设备连接，本分支不加载 MaaCore。此能力在单个 Maa Verge 窗口内使用，无需为每个模拟器另开一份应用。

## 使用方法

1. 在模拟器的多开管理器中启动所需实例，并开启 ADB。
2. 在「设备 → 当前设备」点击「发现设备」，检查「本次发现」中的各已启动实例。已连接设备单独列出；历史连接默认折叠，不表示设备仍在运行。可把发现的设备「保存为多开实例」，或通过页首「管理多开」进入「多开管理」手动添加、编辑、连接或断开实例。「MaaFramework 截图增强」默认「自动识别（推荐）」；Windows MuMu 从管理器读取实际 ADB 端口、名称和编号，支持高索引、非默认端口及多个安装目录，雷电结合 `list2` 与实例所属的 ADB 监听端口核实设备。自动模式连接时按当前实例核对 SDK，无需手动填写增强目录和编号。需要自定义时在「连接设置」明确选择要编辑的实例，手动选择 ADB 或增强截图；MuMu、雷电增强截图必须使用各实例对应的编号，也可为不同实例选择不同安装目录和 ADB。
3. 连接各实例，在「任务」列表勾选任务表后点击页头「运行」：每张表均可多选实例，已绑定表限绑定范围，未绑定表临时选择，底部「多开执行」也保留同一入口。进入「执行监控」后，在线设备与曾连接的离线设备统一显示在设备列表，标题旁汇总设备总数与执行中数量；已连接设备用绿色「已连接」标记，执行状态单独显示。点击设备后在下方查看当前的任务表、作业或工具。离线设备显示已离线，空闲设备显示当前没有任务，最近执行通过单独入口查看。可勾选设备批量停止，或从右侧抽屉合并查看所选设备的日志。
4. 点击设备的「查看执行」，在设备列表下方查看逐任务结果、材料与基建反馈；切换设备即可查看其他实例。空闲或离线设备可点击「查看上次执行」，再通过「查看当前执行」返回当前状态；更早的历史执行可在「执行记录」中筛选或搜索。

没有实例清单，或清单全部由自动识别生成时，自动连接继续发现新启动的本机实例。只要包含手动新增或编辑过的实例，自动连接就限定在已保存清单内逐项尝试，失败单独显示并继续其他项。单独“发现设备”始终可检查本机候选，连接已监听端口的 ADB 传输后刷新列表，不启动游戏或任务。Windows 自定义安装目录可从已运行模拟器的进程路径定位内置 ADB，无需为每个实例安装一份 platform-tools；未识别的安装布局仍可手动选择 ADB。

自动连接开关位于「连接设置」，手动清单启用时的连接按钮显示「连接已保存实例」。任务表中的开始唤醒只编辑游戏客户端、是否启动游戏等任务参数，设备连接设置统一从设备页修改；账号切换等未迁移选项可以保留，执行前明确阻断。从任务页可以直达绑定设备的配置，未绑定时定位顶部所选设备。

同一张任务表可以绑定多个实例，并在这些实例上独立执行；一个实例也可以绑定多张任务表，启动时选择其中一张。未绑定的表可以临时选择任意实例。绑定共用任务与客户端参数，需要不同任务配置时可复制任务表再分别绑定。绑定不占用设备，每台设备实际执行时仍保持独占；逐项解绑、定时目标与兼容规则见[任务表与设备绑定](task-device-bindings.md)。

## 配置与隔离

- 全局连接设置继续作为没有独立配置的设备的默认值。独立实例配置持久化在本机 `Settings.deviceProfiles`，按标准化地址选择对应连接配置，不把全局增强截图编号套到所有实例。当前截图与触控统一保存在各自的 `connection.framework`，截图的 `capture.method: 'auto'` 表示自动识别，触控默认 MaaTouch，两项独立选择。实例配置的 `autoDetected:true` 表示清单由发现生成，用户编辑后转为手动管理，不代替截图选项。旧字段的迁移规则见[连接设置](connection-settings.md)。
- MuMu、雷电自动增强截图只针对已核实实例和存在本机 SDK 的 Windows 安装，雷电还要求默认 ADB 端口归属 `list2` 报告的实例进程。每次连接重新核对，已配置的增强接口失败会明确报错，不静默降级；需要普通截图时可显式改选 ADB。
- 每个实例只允许一个活动执行和一个控制者。常驻 Controller 从连接成功到明确断开持续持有共享用户数据目录下的设备租约，结束业务或 Debug 会话后保留空闲连接；稳定锁文件不会删除。同一 ADB serial、已确认的端口别名或同一 MuMu SDK 实例的桥接别名共享租约，不能用不同显示名称绕过排他控制。MuMu 通过管理器元数据与同一 MuMuNxDevice PID 的监听端口确认别名，发现列表只保留该实例一项；不同 PID 的多开设备独立保留，不把普通 `16384`、`5555`、`7555` 端口全局视为同一设备。设备租约跨进程、开发工作树和业务数据根共享。
- 多实例可同时提交同一任务表；每次启动单独保存参数快照和请求去重键，之后修改任务表不会改动已在执行的实例。
- 停止只发送到对应实例的 worker；其他实例继续。回调即使具有相同的原生任务 ID，也只影响其来源设备的当前执行。
- 各实例固定使用连接时选择的不可变资源代与客户端视图，不覆盖活动文件。修改连接配置用于下次连接，需先停止执行、结束控制会话、断开再重连；其他实例独立执行。正式任务按自己的快照核对客户端和完整参数，当前官服／B服以外的未迁移任务会在整表预检阻断，不能把连接成功当成该客户端游戏流程已经可用。
- 消耗上限按**每次执行**分别检查，默认均为 0；在多个实例上重复执行带消耗的任务表，会分别使用各次授权额度。
- 任务表「查看执行」和底部「运行详情」统一进入执行监控并选中运行设备；切换监控设备或顶部设备会更新下方当前执行。历史入口保留所选的准确记录，后台启动其他实例不会替换它；日志和画面在右侧抽屉打开，关闭后返回原上下文。

## 当前边界

目前管理的是已经启动、可通过 ADB 访问的模拟器实例；Maa Verge 不自动创建或启停模拟器。自动发现只检查管理器元数据、有限默认端口或配置提供的本机回环候选，不扫描端口范围。MuMu 管理器不可用时保留诊断并继续其余发现路径；其他地址可手动配置。增强截图按管理器实际端口优先核对 SDK 实例，不以简单端口等差公式推断全部多开实例。

应用、MaaFramework 和游戏资源分别更新。Framework 与资源更新先暂存、校验完整不可变代际，等待所有活动设备及识别进程空闲后激活，再按原连接配置重连；候选或激活失败按更新流程保留／恢复旧代。有效更新生效后，某个设备重连失败会单独报告离线，不把该设备错误改成组件校验失败。运行中的战斗或业务上下文不会迁移到新代，也不提供逐设备滚动切换。

多开本身不要求 Windows 增强截图，普通 ADB 路径面向 Windows/macOS/Linux，MuMu／雷电增强接口仍受 Windows、SDK、版本和实例编号限制。当前开发验证使用隔离的合成设备与 Framework worker；真实多开模拟器、不同客户端及各宿主仍需分别验收，不能把合成通过视为账号操作已验证。

历史发现修复曾在一个 Windows MuMu 实例上实测，使用的是迁移前的 MaaCore 连接路径；该事实只作为历史保留，不代表当前 MaaFramework 路径或真实多开通过验收。具体记录见[自动连接的历史验证](emulator-connection.md#历史验证旧-maacore-路径)，当前结果以[开发状态](STATUS.md)为准。
