# 工具箱与定时计划

核对日期：2026-11-04。`feat/atomic` 的设备执行统一使用 MaaFramework；工具箱当前提供手动公招计算和既有数据管理。完整仓库/干员扫描、设备公招标签识别、库存保持和小游戏执行尚未迁移，启动前明确阻断，原配置与历史继续保留。任务与字段的迁移范围见[MAA 兼容说明](maa-compatibility.md)。托盘驻留和切换页面不会停止应用服务中的调度。

## 工具箱

进入工具箱后，先选择目标设备。页面读取该设备的客户端、配置和已有缓存，并检查连接与控制权；查询失败可点击「重新检查」。设备执行整张任务表、人工点击、连接或 MaaFramework 切换期间，设备操作入口保持占用，任务表内部两条任务之间也不会释放控制权。

设备忙时，仍可查看、搜索和导出上次成功识别的数据。切换设备或客户端后重新读取对应缓存，不能把另一设备或客户端的旧结果当成本次结果。手动公招计算仅使用本地招募资源与历史干员潜能，不建立设备连接或取得设备控制权。

| 工具     | 当前可用行为与执行边界                                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 仓库     | 查看既有数量和采集时间，支持搜索及 JSON、ArkPlanner、Lolicon、Markdown、CSV 导出；新的完整扫描在预检时阻断                                     |
| 干员     | 查看既有头像、持有、星级、精英化、等级和潜能，支持搜索、持有筛选、复制及 JSON、Markdown、CSV 导出；新的完整扫描在预检时阻断                    |
| 公招计算 | 将「输入方式」切换为「手动选择标签」，最多选五个有效标签，计算最多三个标签的组合、最低星级和候选干员，并显示已有潜能。设备标签识别入口尚未迁移 |
| 库存保持 | 保留每组最多 29 项目标、材料数量、明确关卡、顺序及药剂/源石上限等配置；完整库存扫描与自动补货尚未迁移，不能启动                                |
| 数据管理 | 查看所选设备和客户端的仓库/干员采集时间、当前资源版本，管理既有导出并刷新活动与关卡导航；仓库/干员识别刷新执行仍受迁移预检阻断                 |
| 小游戏   | 保留已激活资源提供的像素画、隐秘战线入口与结局/分支设置；完整执行尚未迁移，资源中存在原入口也不会开放执行                                      |

手动公招计算保存为独立工具记录，不创建任务表，不确认招募、不刷新标签、不使用加急许可。它需要本地已安装的有效招募数据；缺少资源或标签无效时显示错误。需要自动公招时，应使用任务表中已迁移的公开招募流程，其许可、标签保护和计时器边界见[MAA 兼容说明](maa-compatibility.md)。

未迁移工具在前端调用兼容预检，服务端启动入口再次检查；拒绝发生在创建新工具记录、连接设备或输入之前，不改写已有成功结果。原有快捷识别任务表仍可查看、编辑和保存，执行同样遵守整表兼容门禁。

干员头像按干员 ID 从当前官方资源读取，按需加载并缓存；缺失或解码失败使用默认图标。启用新资源后刷新缓存，图片字节不写入业务结果或数据库。历史条目的持有、练度与采集时间沿用保存结果，未识别练度继续显示「未识别」，不能从当前资源名单推断账号的实际持有情况。

旧版库存保持的「先刷新仓库」「按达成率排序」「仅执行首个不足项」「活动期间跳过」及消耗限额保留为参数，不代表当前已有完整执行实现。既有库存结果中的原始数量、掉落推算、采集时间与逐项目标保留用于历史查看；旧的扫描或掉落回调已退出当前执行链，不会作为本次成功识别或新增库存的证据。药剂与源石预算默认均为零。

有效配置即时保存。识别缓存按设备与客户端隔离，沿用确认换号后的失效边界。刷新「识别结果」读取的是已保存数据；它与启动新的游戏内扫描不同。未迁移、失败或停止的请求不会生成一份新的成功采集结果。

## 每日定时

打开已保存任务表的「定时计划」页签，选择设备、时间并添加。支持八组以上，可继续增加；「查看全部定时」汇总其他任务表的规则。任务表可绑定多台设备，每条定时选择其中一台；同一张表可为不同设备分别建立规则。未绑定任务表可选任意设备。解除一项绑定时，只停用不再满足范围的规则；不会替换目标。详见[任务表与设备绑定](task-device-bindings.md)。每行显示下一次触发和最近结果，可修改时间、任务表、设备、启用状态或删除。

定时采用电脑本地时间，每天执行一次。仅本次启用/跳过是会话内覆盖，消费后恢复保存设置，应用重启后清除。旧 `Plan.schedule` 字符串继续保留兼容，不会转换成新规则。

- 到点读取已保存任务表并固定任务快照，先检查全部启用任务的类型、参数和资源前提；其中任意一项未迁移或资源不足，整次执行失败，前面的任务也不会先运行。自定义基建文件在正式启动前重检并固定文档快照，保留原文件。
- 普通定时遇到设备占用时记录跳过，不排队。
- 全局「强制定时启动」启用后，整表预检通过才进入 10 秒取消倒计时，可选择提前显示窗口。倒计时结束后再次预检，通过后才停止目标设备当前任务，等待 MaaFramework 安全空闲并准备连接；正式启动前仍重检全部任务。最终按同一设备客户端先关闭游戏，再执行目标任务表。停止的操作不恢复，启动游戏由目标表内「启动游戏」负责。
- 未迁移尾项、未知自定义基建干员或自动补位资源缺口等静态问题，会在强制定时的倒计时、停止现有执行和设备输入之前拒绝。原任务表与当前执行继续保留。
- 提前两分钟准备目标连接前，同样先检查整张表的兼容性；不会为了不支持的配置连接设备，也不提前中断已有执行。
- 定时通知默认关闭；开启后默认提前五分钟，可选 1–1439 分钟。应用内提示保留，桌面系统通知还受“设置 → 通知与远控”的总开关和定时分类开关控制，详见[系统通知](notifications.md)。
- 同设备同刻按列表顺序执行第一条，其他记录冲突跳过；不同设备独立执行。
- 退出、休眠、时钟跳变错过的分钟不补跑。触发键及运行快照在原生操作前持久化，重启、重复轮询和时钟回拨不重复执行同一每日触发；中断而结果未知的调度不会自动重放。
- 删除任务表、设备或关联连接配置时，停用对应规则并显示原因；不会自动改用其他目标。

## Windows 唤醒

「Windows 提前五分钟唤醒并启动应用」默认关闭。启用后，桌面外壳通过 Windows 任务计划程序注册每日唤醒，程序路径与数据根参与任务名隔离；启动及配置变化时同步，关闭开关时删除本实例任务。界面显示实际注册状态，权限或系统错误会显示失败。

注册仅包含已保存启用的规则。临时跳过可能仍会唤醒电脑，但服务不会执行该次游戏操作；临时启用不产生重启后仍有效的规则。自动启动通过已有单实例入口协调，准备和执行阶段请求系统保活。是否真正唤醒还受电脑电源策略、唤醒计时器和硬件影响。

macOS/Linux 仅支持应用运行期间调度，本版不支持系统唤醒。Windows 隔离任务注册/修改/清理有自动测试；实际休眠恢复、真实游戏及其他平台桌面行为须单独验收。
