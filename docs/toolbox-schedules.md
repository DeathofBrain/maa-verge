# 工具箱与定时计划

行为基线为 MAA v6.20.0 Windows 客户端。以下功能由 TypeScript 服务执行，托盘驻留和切换页面不会停止调度或工具；Python 调试参考后端不提供新增接口。

## 工具箱

进入工具箱后，先在「目标设备」选择设备。页面随后检查连接与控制权，检查完成后开放工具操作。查询失败可点击「重新检查」。设备执行整张任务表、其他工具、人工点击、连接或核心切换时禁用启动；不会插队或排队。任务表内部两条任务之间的空闲也不会释放控制权。

设备忙时，仍可查看、搜索和导出上次成功识别的数据。启动请求还会在服务端再次检查并取得独占权。切换设备后重新检查并读取该设备的数据；已经开始的工具继续使用启动时的设备、客户端和配置。不同设备可同时运行。

| 工具 | 使用方式与结果 |
| --- | --- |
| 仓库 | 独立识别；展示数量和采集时间，支持搜索及 JSON、ArkPlanner、Lolicon、Markdown、CSV 导出 |
| 干员 | 独立识别；展示头像、持有、星级、精英化、等级和潜能，支持搜索、持有筛选、复制及 JSON、Markdown、CSV 导出 |
| 公招计算 | 识别设备标签或手动选择最多五个标签，列出最多三个标签的组合、最低星级和候选干员；已识别干员的潜能一并显示。不会确认招募、刷新或加急 |
| 库存保持 | 每组最多 29 项目标，配置材料 ID、数量、明确关卡、顺序及药剂/源石上限；启动独立补货并显示逐项达标情况 |
| 数据管理 | 按所选设备和客户端查看仓库/干员采集时间、当前资源版本；提供识别刷新、数据导出及活动与关卡导航刷新入口 |
| 小游戏 | 根据已激活资源开放像素画和隐秘战线；设置结局/分支后直接开始，可停止。核心流程结束不代表已经验证游戏奖励，须核对设备结果 |

这些操作保存为独立工具记录，不会创建任务表。原有快捷识别任务表保留，可继续手动使用。

干员头像按干员 ID 从当前 MaaResource 读取，固定尺寸占位、按需加载并缓存；缺失或解码失败使用默认图标。启用新资源后刷新缓存，图片字节不存入业务结果或数据库。未持有条目来自核心最终完整名单，未识别的练度显示「未识别」。

库存保持默认先刷新仓库，再计算缺口并按配置排序。支持按达成率排序、仅执行首个不足项、活动及资源收集全开期间跳过；导航判定关闭的关卡会跳过。药剂、源石默认均为零，未开放无法严格限量的临期药选项。

库存以原始识别值为基准，累计已确认的掉落增量；重复回调不会重复累计。仓库中「掉落推算」与原始数量分别显示，采集时间保留。结果区分全部达标、部分完成、用户停止、失败或结果未知；成功流程仍有不足项时不会宣称全部完成。停止/失败不丢弃已确认掉落。

有效配置即时保存。最终识别结果必须同时通过数据校验、任务成功和核心/异步调用空闲确认，随后原子保存；失败保留上次成功结果。结果按设备与客户端隔离，沿用现有确认换号时的缓存失效边界。

## 每日定时

打开已保存任务表的「定时计划」页签，选择设备、时间并添加。支持八组以上，可继续增加；「查看全部定时」汇总其他任务表的规则。任务表绑定设备时，定时必须选择同一设备。每行显示下一次触发和最近结果，可修改时间、任务表、设备、启用状态或删除。

定时采用电脑本地时间，每天执行一次。仅本次启用/跳过是会话内覆盖，消费后恢复保存设置，应用重启后清除。旧 `Plan.schedule` 字符串继续保留兼容，不会转换成新规则。

- 到点读取已保存任务表，固定启用任务的执行快照；之后编辑影响下一次执行。
- 普通定时遇到设备占用时记录跳过，不排队。
- 全局「强制定时启动」启用后提供 10 秒取消倒计时；可选择提前显示窗口。倒计时结束后停止目标设备的任务表或工具，等核心与异步调用结束，先关闭当前客户端游戏，再执行目标任务表。停止的操作不恢复，启动游戏由目标表内「开始唤醒」负责。
- 提前两分钟准备目标连接，不重启 Maa Verge，不提前中断设备。
- 通知默认提前五分钟，可选 1–1439 分钟；应用内提示和桌面系统通知同时发出。
- 同设备同刻按列表顺序执行第一条，其他记录冲突跳过；不同设备独立执行。
- 退出、休眠、时钟跳变错过的分钟不补跑。触发键及运行快照在原生操作前持久化，重启、重复轮询和时钟回拨不重复执行同一每日触发。
- 删除任务表、设备或关联连接配置时，停用对应规则并显示原因；不会自动改用其他目标。

## Windows 唤醒

「Windows 提前五分钟唤醒并启动应用」默认关闭。启用后，桌面外壳通过 Windows 任务计划程序注册每日唤醒，程序路径与数据根参与任务名隔离；启动及配置变化时同步，关闭开关时删除本实例任务。界面显示实际注册状态，权限或系统错误会显示失败。

注册仅包含已保存启用的规则。临时跳过可能仍会唤醒电脑，但服务不会执行该次游戏操作；临时启用不产生重启后仍有效的规则。自动启动通过已有单实例入口协调，准备和执行阶段请求系统保活。是否真正唤醒还受电脑电源策略、唤醒计时器和硬件影响。

macOS/Linux 仅支持应用运行期间调度，本版不支持系统唤醒。Windows 隔离任务注册/修改/清理有自动测试；实际休眠恢复、真实游戏及其他平台桌面行为须单独验收。
