# 原 MAA 功能覆盖与验收

核对日期：2026-11-04。原版功能盘点固定到官方 **v6.21.2**，详见[全功能与设置清单](maa-feature-inventory.md)。`feat/atomic` 的产品执行统一使用 MaaFramework、应用维护的 JSON Pipeline 和 TypeScript Custom；已移除 MaaCore 加载、旧 worker 命令和自动回退。官方 MAA 的资源、模板、物品、招募与基建数据继续作为不可变资源代使用，适配器记录来源、摘要、原适配基线及实际资源版本。

原任务类型和参数可保存，不代表当前执行器已覆盖其全部语义。兼容检查在取得设备控制权前扫描整张表；未迁移的任务或主动参数明确阻断执行，原配置、库文件、计划、工具缓存与历史继续保留。关闭的任务行不授予设备动作，编辑其他字段不会删除未显示的参数。

## 常用流程的当前边界

下表说明实现与合成验证范围，均不代替真实游戏和各平台验收。

| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| CloseDown | 同一客户端默认语义；独立等待 controller `stop_app` 成功回执                                                                                        | 只证明 force-stop 动作成功，不声称读取并验证 PID；不退出 Maa Verge 或模拟器                                                                                                            |
| Fight     | 当前已选关卡；普通/S 主线0–17章和 CE/LS/CA/AP/SK、PR-A至D 常用路由；精确关卡名复核；×1–6倍率，按游戏实际场次计数；材料目标累计；明确药/石额度      | 活动、剿灭、难度切换、自动倍率/剿灭票、临期药、DrGrandet和数据上传仍阻断。倍率、目标材料图标及数量布局在输入前检查；数量歧义、裁切掉落和未知结算不能记零或继续刷                       |

完整业务流程由已登记 JSON 组合 L3 事件；Tasker/Context 负责节点流转。开战、招募和购买后的未知结果立即停止，不自动重放提交。长战斗在独立根图之间分段只读等待，最多30分钟；原 Debug 的 `workflow.fight.current_stage` 继续保持其最多20场的旧契约，正式旧任务使用独立批次入口，不截断原 `times` 上限。

## 参数、文件与消耗兼容

- `Task.enabled` 缺省仍兼容为启用；`params.enable=false` 同样跳过。全部关闭可以保存，开始执行须至少一条启用任务。未知字段保留在 `params`，未经适配的主动语义阻断执行。
- 药、源石、信用与新招募许可先由宿主持久预留，再提交一次。默认药/石/信用额度零；公招 `times` 明确限制本次新招募许可，非加急时只处理最多四个槽位。确认丢失、取消或后置证据未知时保留占用，不重试或自动退款。
- `medicine_expire_days`/旧 `expiring_medicine` 是独立临期药行为，不能当普通药数量；正值继续拒绝。原 `expedite_times` 在上游不构成加急总上限，因此 `expedite=true` 仍拒绝。
- 好友“每日一次”按设备、客户端和04:00游戏日持久去重，并兼容旧访问时间。先占用再操作，失败或未知也保守占用；这只表示当日自动尝试已占用，不冒充已验证领取信用。
- 自定义基建文件由安全、有大小边界的读取生成文档与SHA-256快照。原 `filename`、`plan_index`、设施子集和心情阈值保留；执行固定同一快照，不重写原文件。空名单且未开启自动补位表示保持原房间；文档中的元数据不改变执行范围。
- 新建任务保持关闭数据上传；存量上传开关原样保留，当前开启上传的执行请求明确阻断。本轮合成验证未进行真实上传、设备操作、自动连接、SDK下载或付费模型调用。
- 保存、预检、正式执行分开校验。动态章节、倍率和材料资源在取得 controller 前检查；实际执行仍重新检查同一不可变资源。应用更新、MaaFramework更新和资源更新独立，不以引擎版本相同跳过资源更新。

## 验证与后续门槛

automation 的合成测试覆盖受控启停、登录稳定窗口、逐场战斗与只读长等待、消耗预留、掉落目标、招募逐槽/计时/保护、商品策略、好友日去重、奖励和未知后不重放。浏览器行为测试使用显式注入的隔离 runtime；历史结果直接恢复为夹具，不执行未迁移任务来伪造历史。

已安装官方资源目录的只读检查只证明字段、模板、数据及目录门禁可用。真实验收仍须记录 MaaFramework实际版本、官方资源commit、宿主系统、连接方式、客户端、脱敏参数、独立成功证据和停止/失败结果。未验证的平台、外服、游戏界面和高级模式保持待验收，当前状态为开发预览。

原版接口、全部设置与剩余差距分别见[全功能清单](maa-feature-inventory.md)、[任务设置对照](maa-task-settings.md)、[自动化维护指南](../services/automation/README.md)与[当前状态](STATUS.md)。
