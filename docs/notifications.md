# 系统通知

桌面应用在 Windows、macOS 和 Linux 使用系统通知。“设置 → 通知与远控”提供总开关和四类通知偏好，切换后自动保存并立即生效：

- 执行结果：任务表、作业和独立工具执行结束、失败或中断。
- 目标实例未就绪：向指定实例运行任务表时，仅在本地模拟器端口已确认不可达、没有其他控制者占用时提醒确认对应实例已启动。远程设备、普通连接失败、自动发现失败、运行中断线及手动断开均不发送连接异常系统通知。同一次启动请求不会重复提醒；端口不可达不代表已确认模拟器进程没有运行。
- 更新结果：应用或组件更新准备完成、组件生效及更新失败。应用、核心和资源分别处理。
- 定时提醒：提前通知和强制启动倒计时；提前通知仍需在定时计划中开启。

默认启用全部类别。关闭系统通知不会删除执行记录或关闭应用内提示。普通进度变化、历史快照和页面切换不会补发通知；执行结束不代表游戏通关或所有动作成功，具体证据仍以执行记录为准。

通知发送者使用 Maa Verge 应用身份。Windows 为当前用户注册从应用标识派生的固定通知身份 `<应用标识>.notifications`，开发版和便携版也不借用 PowerShell；Linux 使用 Maa Verge 应用名；macOS 使用 Maa Verge 应用包标识，不借用 Terminal，未打包的开发程序无法取得自身应用身份时会报告错误。

Windows 在顶部应用名左侧单独注册 32×32 Logo PNG，通知正文显式使用 256×256 Logo；Linux 也显式传入 Logo，macOS 从应用包读取图标。Windows/Linux 将内嵌图标按内容标识保存到系统本地应用数据目录的 `notification-icons`，不依赖源码目录或安装包旁的额外文件；切换业务配置、更新或退出时保留，供通知中心中的历史消息读取。新发出的通知会携带内容图标，既有历史通知不会重发。

Windows 旧通知身份曾将 EXE 当作图标，系统可能持续缓存空白的顶部图标；新版固定使用通知专用身份，从首次注册就提供有效 PNG，不随应用版本或 Logo 内容改变身份。应用内已保存的通知偏好继续生效；Windows 系统通知开关按新身份独立管理，曾在系统中单独关闭 Maa Verge 通知的用户需对新版发送者重新设置。

可在同一设置页检查并启用通知通道，或发送固定内容的测试通知。普通浏览器没有桌面通知入口；通知发送错误会明确反馈。系统通知设置、勿扰模式、桌面会话或通知服务可能影响投递，通道可用不代表通知一定展示。未收到测试通知时，在操作系统设置中允许 Maa Verge 通知；托盘驻留时应用仍能提交通知。开始退出或安装应用更新时立即停止新通知，等待投递的通知和关闭服务产生的事件也不会再发送。

通知由桌面宿主消费实时事件并过滤、去重，偏好保存在业务设置的 `notifications` 字段。目标实例未就绪偏好沿用 `deviceErrors` 字段，仅接受业务服务确认的 `run.connection_failed` 事件及 `emulator_unavailable` 原因，不根据通用设备错误文本推断。旧配置自动补默认值，旧客户端保存其他设置时保留通知偏好；原有定时通知也走同一总开关和分类开关。前端只能调用固定的状态查询和测试命令，不能指定任意通知消息。

常规测试使用隔离事件和桌面桥夹具，不向操作系统实际发送通知。三平台实际通知呈现仍需在各自桌面环境单独验收。
