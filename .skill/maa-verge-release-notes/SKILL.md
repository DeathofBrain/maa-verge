# Maa Verge Release 说明

生成可直接用于 GitHub Release 的简体中文 Markdown，保存到仓库的 `docs/releases/<tag>.md`。参考原 MAA [v6.20.1 Release](https://github.com/MaaAssistantArknights/MaaAssistantArknights/releases/tag/v6.20.1) 的分类更新、PR / 作者署名和折叠结构；保留下载表，更新内容默认每项一句短句。

本 skill 目录的 `../..` 是仓库根目录。下文代码路径均相对仓库根目录；模板与示例链接相对本 skill 目录。

## 输入与维护方式

- 按根目录 `AGENTS.md` 了解项目边界，结合 `PLAN.md`、`docs/STATUS.md` 与本次明确的目标版本、提交或发布分支确认范围。修改已有说明时，先读对应的 `docs/releases/<tag>.md`。
- 新建版本说明从 [assets/release-notes.md](assets/release-notes.md) 起草；已有正文按本次要求修改。模板是结构参考，替换占位内容并删除不适用段落。可参考已整理的 [v0.1.0](../../docs/releases/v0.1.0.md) 的下载与许可信息组织方式，不沿用其篇幅；其中功能、数字、依赖版本和文件名仅属于该版本。
- 规范与模板统一在本 skill 下维护；`docs/releases/README.md` 和 `CONTRIBUTING.md` 只保留入口，避免出现多份不同规则。

## 正文顺序

1. **版本与重要提示**：版本名、开发预览 / 正式版状态，以及影响安装或升级的注意事项。
2. **本版亮点 | Highlights（可选）**：仅有重要变化时保留，每项一句概括，不展开成长段落，也不重复下方条目。
3. **下载与安装**：保留下载表，按平台、架构列出实际安装包直链和校验清单；简要注明最低系统目标、必要系统依赖与 Source code 的用途。Windows 普通安装优先推荐 EXE，macOS 区分 Apple Silicon 与 Intel。
4. **首次使用或升级说明**：只保留本次需要用户执行的步骤。
5. **已知问题与限制**：保持展开，说明用户会遇到的缺口和适用平台，提供 Issue 入口。
6. **更新内容**：当前版使用 `<details open>`；按“新增 | New”“改进 | Improved”“修复 | Fix”“文档 | Docs”“其他 | Other”分类，每项一句，没有内容的分类省略。
7. **许可与对应源码**：单独折叠，保留本版源码 / 锁文件、依赖许可位置、嵌入运行时与引擎的精确源码及重建入口。
8. **完整变更**：提供上一发布标签到本版的 compare 链接；首版提供源码标签链接。
9. **上游引用与版权**：全文最底部常显，使用模板中的署名格式，按实际引用情况调整。

## 内容约定

- 检查上一发布版本到目标提交的记录与 diff，只写该版本最终有效的行为。同一功能的开发调整合并为一条，完整撤销的内容删除。
- **新增、改进、修复等默认每条只写一句短句，直接说明增加了什么、改善了什么或修复了什么问题。** 选择用户能感知的变化，合并相关条目；不逐提交堆砌，不展开实现细节、排查过程或完整前后行为说明。需要使用步骤时链接对应文档。
- 首次开放的功能描述最终能力；“修复”只用于已发布版本存在的问题。首个发布版通常只需要“新增”，不为凑齐分类虚构条目。
- 不把后续分支功能、待办计划或较新验证结果混入旧版本说明。已有版本勘误保留原发布日期、功能范围和已知限制。
- 版本号、发布日期和 GitHub Pre-release 标记分别核对；`v0.1.0` 也可以是开发预览。依据本次明确的发布目标填写，缺少新版本目标时不自行猜测。
- 使用界面中的正式名称，仅在影响理解时简短补充平台、模拟器、客户端、只读或需手动执行等条件。应用、MaaCore 和游戏资源的更新范围分别说明。
- 根据本版构建清单或已上传资产核对下载文件名、大小写、架构与格式，不直接替换旧版本号猜测。Release 中的链接使用完整 URL；源码、文档和图片尽量固定到本版标签或提交。
- **Release 正文和模板省略“构建来源与验证范围”、CI 运行链接、测试数量等工程记录，相关记录留在 `docs/STATUS.md`。** 用户需要知道的平台限制与已知问题仍直接说明。
- 许可块保留应用 AGPL-3.0-only、第三方许可、本版 Bun / JavaScriptCore 精确来源及重建入口，按实际依赖填写。
- **最底部列出 MAA / MaaCore 与 MaaResource 项目地址、核心 / 资源复用及协议 / 配置 / Release 结构参考范围。** 分别注明上游原作者与贡献者、本项目自有代码的版权和相应许可；游戏素材及第三方内容保留各自声明，不能统一归入应用许可。保留独立项目说明，不编造版权年份或权利人，并区分许可文本与项目代码的版权。

## PR 与贡献者署名

- 他人通过 PR 提交的 feat、fix 等变更，在对应条目末尾标注可点击的 PR 编号和 `@GitHub用户名`，格式为 `（[#123](PR完整URL)） [@username](https://github.com/username)`。
- 核对本版实际合入的 PR、对应变更及贡献者 GitHub 用户名，不由提交显示名推测用户名。已核实的作者署名保留；没有 PR 但作者可核实时可只标作者，信息不明时不编造编号或署名。
- 在实际贡献条目后直接署名，无需为此另写长段致谢。模板中的 PR 编号和用户名是占位内容，只有对应变更确有贡献记录时才替换保留。

## 核对与交付

- 核对版本范围、资产文件与链接，清除占位内容、空分类和不适用段落；检查表格与折叠块配对，以及版权署名位于所有折叠块之后。正文排版有较大调整时可使用 GitHub GFM 渲染接口核对结构。
- 使用 `git diff --check` 检查文档变更，将实际核对方式和结果写入 `docs/STATUS.md`。纯文案修改无需启动产品、连接设备或重建安装包。
- 本 skill 的范围是本地版本说明与相关文档维护。线上 Release 的创建 / 修改、资产上传及标签操作按用户对此操作的现有授权和项目发行流程执行；撰写文案本身不扩大授权，也不意味着已同步线上正文。
