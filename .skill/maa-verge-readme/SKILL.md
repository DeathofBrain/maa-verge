# Maa Verge 用户 README

让普通用户看完后知道软件能做什么、去哪里下载、选哪个安装包、怎样开始使用，以及出错后如何处理。

## 先读当前文件

- 将项目根目录的 [README.md](../../README.md) 作为结构、语气和用户选择的首要参照。每次执行都重新读取，保留用户后续调整，不恢复历史草稿中已被删除的表述。
- 按 [AGENTS.md](../../AGENTS.md) 检查已有改动，并阅读 [PLAN.md](../../PLAN.md) 与 [开发状态](../../docs/STATUS.md)。计划用于了解路线，状态用于识别开发进展；它们都不能单独证明功能已进入发行包。
- 以用户指定的发行版为准；未指定时沿用 README 正在介绍的发行版。更新版本基线前，确认对应 Release 和安装包已实际发布。

## 读者与表达

- 使用简体中文和界面中的中文名称，用「设置 → 更新」这类路径说明操作。首次出现的术语只解释到能完成操作的程度。
- 正文围绕下载、安装、连接模拟器、执行任务、更新与反馈展开。技术栈、进程、协议、测试数量和开发命令留在开发文档，文末提供链接。
- 保留当前居中 Logo、项目标题、简短副标题及下载、快速开始、常见问题、反馈导航。副标题当前为「正在努力开发中」；未要求调整品牌文案时，不替换为营销口号。
- 功能条目用用户能感知的行为说明价值，避免宣传语、实现细节和过度承诺。限制放在相关位置简短说明，详细验证范围链接到版本说明。
- Agent 沿用当前 README 的产品表述：后续开发目标，当前暂不可用。内部规则提案或 mock 不作为可用 AI 能力宣传；只有实际发行能力发生变化时才更新此结论。

## 沿用当前组织方式

默认沿用以下阅读顺序，根据用户要求与版本变化精简，不机械增加章节或固定条目数量。

1. **项目开头**：Logo、标题、副标题、常用入口，一段用途介绍和简短版本状态。
2. **下载与安装**：优先给 Releases 入口；用表格列系统、架构、文件特征及安装方式。说明 Assets 与 Source code 的区别、必要系统组件、首次联网下载和模拟器准备。签名与兼容性提示以发行版实际情况为准。
3. **能做什么与界面预览**：保留简短功能列表；主页图直接展示，其他截图默认放入折叠的 `<details>`。统一说明测试数据截图不含真实账号信息，不将其当作实机结果。
4. **快速开始**：围绕准备模拟器、组件就绪、连接设备、新建任务表、手动开始执行展开。保留必要的零理智药/源石默认值、停止结束当前队列、多开时单设备单控制者等提示，不重复安装章节。
5. **常见问题**：用用户会问的问题作标题，直接给出可操作的处理方式。按需求维护连接、下载、更新、定时与 Agent、备份、联网与掉落汇报等内容。
6. **遇到问题**：链接 Issues，说明反馈需要的版本、模拟器、步骤和错误信息。诊断导出入口使用该发行版实际按钮名称，分享前提醒检查个人信息。
7. **参与与致谢**：链接贡献、开发、状态与计划文档，保留上游致谢、许可证、独立项目身份，以及文末 Logo 来源与权利声明。

## 核对发行版事实

- 核对实际 Release 的资产、发行说明及对应 Git 标签中的文档和代码；必要时用 `git show <tag>:<path>` 对照界面按钮、配置路径与默认行为。不要只看当前工作树或 `package.json`。
- 安装包类型、架构、最低系统、签名、首次下载、应用升级、数据目录和诊断入口均随版本核实。不要永久写死 v0.1.0，也不要把开发分支新增的配置位置或按钮当成已发布功能。
- 应用、MaaCore、游戏资源分别说明更新方式。核心版本相同不代表资源没有更新；未配置应用自动更新时，引导从 Releases 下载新安装包。
- 备份说明明确适用版本，指导完全退出后备份整个业务数据目录。不要混用发行版与开发版目录，也不要建议删锁文件或仅复制运行中的数据库。
- 区分本地保存与网络请求。保留活动、下载、更新及掉落汇报的真实行为，不写「所有数据都不会上传」。
- 与特定发行版相关的使用文档链接固定到相应标签；贡献与开发进展链接指向当前仓库文档。只有预览版时也应能从 Releases 列表找到，不假定 `releases/latest` 会指向它。
- 延续现有可用图片与相对路径，避免为 README 引入真实账号截图或无关素材。截图与发行界面存在明显差异时，应说明适用版本或使用匹配图片。
- 区分支持目标、构建成功、安装验证和真实设备验证。没有证据时保留已知限制或省略结论，不补造兼容性保证、验收结果或交付日期。

## 完成检查

- 检查本地文档、图片、HTML 链接、页内锚点和折叠标签；新增或修改的发行文档链接应在对应标签中存在。

- 文档维护使用只读资料核实和链接检查即可；不因撰写 README 启动真实服务、操作游戏、调用模型、下载核心或发布版本。用户另行明确要求的验证按其授权执行。
- 交付时简要说明改动和实际完成的检查，不将文档检查描述成应用或平台验收。
